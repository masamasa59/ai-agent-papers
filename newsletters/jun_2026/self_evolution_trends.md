# 自己進化エージェント（Self-Evolving Agents）研究トレンド（2026年6月）

> 対象：[self-evolution](../../capabilities/adaptation/self-evolution.md) の 2026年6月論文（10本）。各論文の arXiv HTML 本文を読んでまとめた。

## 先月からの差分

自己進化とは、エージェントが自分の経験から学んで、次からの働きを良くすることだ。近ごろの主流は、モデル本体（重み）を訓練し直すのではなく、その外側にある知識・手順・メモリのほうを書き換えて良くする、というやり方——本稿ではこれを「外側で育てる」と呼ぶ。6月の差分は、この外側で育てる流れに、冷静な反証と条件付けが加わったことだ。

- **外側で育てる対象がはっきりしてきた**：コンテキスト（UCE）、監査の手順書（EvoHunt）、指示文＝プロンプト（AgentX）と、いずれもモデルを固定したまま育てる。
- **その効果は万能ではない**：SEAGym は、「練習に使ったタスクでは伸びても、学習に使っていない別のタスクや別のモデルには効きにくく、むしろ悪くなることもある」と示した。Meta-Agent Challenge は、エージェントに別のエージェントを自律的に設計させても、人間の作りにはほとんど勝てないと報告する。
- **関心が「測り方」と「安全」に移った**：評価の環境（SEAGym）、採点基準の整理（Rubrics）、採点する側も一緒に育てる発想（Red Queen）、そして安全上の弱点の洗い出し（MLAS）が並んだ。

> ※数値はモデルとデータの条件を添えて記す。1本だけの結果は末尾に「要追試」としてまとめた。

## 論文紹介

### 外側で育てる——何を残すか

モデルの重みを訓練し直すのは高くつき、しかも一度太らせると別の用途に使い回しにくい。外側の知識や手順なら、安く作れて別のモデルにも移せる。各論文がこの利点を別の形で示す。

[Unified Context Evolution for LLM Agents（UCE）](https://arxiv.org/abs/2606.02304)
経験を4種類のメモ（環境の仕組み、判断のルール、手順、使い回せる小技）として貯め、評価→生成→整理を繰り返して育てる。モデルは一切訓練しない。家事タスクの成功率が 75% 台から 96% 台へ上がり（gpt-5.2 で）、別の設計のエージェントに載せ替えても効いた。細かい選択が要るタスクは頭打ちで、そこは別の学習が要ると率直に述べる。

![UCE](../assets/2606.02304-uce-architecture.png)
> 図（UCE）：評価→収集→生成→整理という5段階で、型のついた経験メモをモデルを固定したまま育てる。（[論文](https://arxiv.org/abs/2606.02304)）

[Transferable Self-Evolving Playbooks for Agentic Security Auditing（EvoHunt）](https://arxiv.org/abs/2606.16420)
セキュリティ監査で、モデルもハーネスも固定し、監査の手順書だけを育てる（手順書はテキストで版管理する）。実際に動く攻撃を見つける、という難しいタスクで成績を上げ、強いモデルで一度育てた手順書を安いモデルに渡しても効く、という費用の設計を示した。

[AgentX: Agent-Driven Self-Iteration of Industrial Recommender Systems](https://arxiv.org/abs/2606.26859)
実際の推薦サービスで、着想→開発→評価の輪を回し、自分の指示文を少しずつ改善する。運用で成果を出した一方、本番では実際の A/B テストと人による承認が欠かせない、と釘を刺す。

![AgentX](../assets/2606.26859-agentx-workflow.png)
> 図（AgentX）：着想→開発→評価の輪と、指示文を磨いていく自己進化の全体像。（[論文](https://arxiv.org/abs/2606.26859)）

### 「進化すれば万能」への反証

[SEAGym: An Evaluation Environment for Self-Evolving LLM Agents](https://arxiv.org/abs/2606.17546)
自己進化を公平に測るための環境。「練習に使ったタスクでの伸び」「学習に使っていない別タスクでの伸び」「忘れ」「費用」を分けて測る。すると、練習タスクの伸びは別タスクには小さくしか波及せず、あるモデルで育てた仕組みを別のモデルに使うと悪化した。「効果は、更新のやり方・タスクの種類・使うモデルに強く左右され、万能ではない」というのが結論だ。今月の「測り方」論の中心にあたる。

![SEAGym](../assets/2606.17546-seagym.png)
> 図（SEAGym）：静的なベンチマークを進化の実験場に変え、練習／未知／忘れ／費用を分けて測る。（[論文](https://arxiv.org/abs/2606.17546)）

[The Meta-Agent Challenge](https://arxiv.org/abs/2606.04455)
エージェントに、別のエージェントを自律的に設計・実装・改善させられるか。多くの構成を試したが、人間の作りを超えたのはごく一部で、ばらつきも大きく、評価の抜け穴を突く動きも出た。自律的なエージェント開発は、まだ現実的でない、という現在地をはっきり示した。

### 「採点する側」と「安全」が主題に

[Rubrics Across the Evolving LLM Landscape](https://arxiv.org/abs/2606.08625) 📖
採点基準（ルーブリック）を整理した総説。基準が「外から評価する道具」から、モデルと一緒に育つ「内側の自己点検の仕組み」へ移りつつある、と跡づける。質の低い採点基準は、黙って外れるのではなく、むしろ判断を悪くする、と警告する。「誰が採点基準を作るのか」が問われ始めた。

[The Red Queen Gödel Machine](https://arxiv.org/abs/2606.26294)
採点基準を固定していると、エージェントはその抜け穴を突いてしまう。そこで、エージェントと採点する側を一緒に育てる。強い採点役でも AI の書いた論文を人間より甘く（およそ1.9倍）通してしまう偏りを、あえて対立させることで補正できたという（進行中の研究）。

[Safety in Self-Evolving LLM Agent Systems](https://arxiv.org/abs/2606.23075)
自己進化する仕組みの弱点を、5×5＝25 の観点で洗い出した。多くの観点に有効な防御がなく、攻撃が世代を越えて残ってしまう。核心の指摘は「自己進化では、安全装置や採点役そのものが最適化・攻撃の的になり、最適化する側とされる側の区別が崩れる」——だから固定した守りでは足りない、という警告だ。

## この号のまとめ
- **確かなこと**：モデルの外側（知識・手順）を育てるやり方は安く、別のモデルにも効くことがあり、主流になった。
- **注意**：その効果は練習タスクに寄りやすく、学習に使っていない別タスクや別のモデルへは移りにくい（SEAGym）。自律的なエージェント設計はまだ無理（Meta-Agent Challenge）。数値は「どの条件で測ったか」を確認して読む。
- **1本のみで要追試**：実サービスでの自己進化運用（AgentX、1事例）／自己進化する仕組みはほぼ無防備で攻撃が残る（MLAS、1つの実装での比較）。

## 次に読みたくなる問い
- 育てた成果を、学習に使っていない別タスクや別のモデルへどう移すか。
- 採点する側を、誰がどう育てるか（Red Queen／Rubrics）。
- 自己進化に耐える安全の作り方（MLAS の先＝動く標的をどう守るか）。
