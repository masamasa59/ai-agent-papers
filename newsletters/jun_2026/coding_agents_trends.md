# コーディングエージェント（Coding Agents）研究トレンド（2026年6月）

> 対象：[coding-agents](../../applications/system/coding-agents.md) の 2026年6月論文（8本）。各論文の arXiv HTML 本文（1本のみ abstract）を読んでまとめた。

## 先月からの差分

コーディングエージェントとは、AI が実際にソフトウェアを書く取り組みだ。ここは、能力の伸びと実運用の難しさが同時に表に出る最前線でもある。6月の8本は、大きく2つに分かれる。ひとつは働き方の変化を扱う大きな絵——人が AI に仕事を任せる（委譲する）方向へ動いている。もうひとつは、エージェントを具体的に強く・安くする工夫だ。

そして両方に、共通の壁が見えた。「1問なら解けても、長い開発になると崩れる」壁と、「書く速さより、書いたものを確かめる（レビューする）ほうが追いつかない」壁である。

- **委譲への移行**：Codex の利用データ、Agentic Software（サービスとしてのエージェント論）、Skills（将来の技能）が、別々の角度から同じ方向を示す。
- **壁は「連続実行」と「検証」**：Agentic Software（長い開発で崩れる）、AI-Native SE（生成物の脆弱性）、Skills（手作業のレビューは当てにならない）が指摘する。
- **地に足のついた改善**：学習の工夫（TMax）、自分の失敗から学ぶ（Socratic-SWE）、文脈を絞って安くする（SeeRepo・FastContext）。

> ※数値はモデルとデータの条件を添えて記す。1本だけの結果は末尾に「要追試」としてまとめた。

## 論文紹介

### 大きな絵：委譲への移行と、その壁

[The Shift to Agentic AI: Evidence from Codex](https://arxiv.org/abs/2606.26959)
実際の利用データから働き方の変化を測った。半年で、半日がかりの仕事を AI に任せる割合が大きく増え（2%台から25%台へ）、多くのユーザーが同時にいくつものエージェントを動かすようになった。「相談する AI」から「任せる AI」へ。生産性を活かす鍵は、モデルの賢さより、任せ方・監督・仕事の割り振りといった運用の設計だ、と結論する（最先端の環境なので一般化には注意）。

![Evidence from Codex](../assets/2606.26959-codex-adoption.png)
> 図（Evidence from Codex）：ユーザー種別ごとの利用の伸び。会話から委譲への移行が見て取れる。（[論文](https://arxiv.org/abs/2606.26959)）

[Agentic Software: How AI Agents Are Restructuring the Software Paradigm](https://arxiv.org/abs/2606.05608)
ソフトの作り方が「あらかじめ人が全部書く」から「AI が実行時に判断して作る」へ移る、と論じる。核心は警告にある——1つの独立した課題では8割超だった成功率が、長く続く開発では4割弱まで崩れる。文脈がずれ、誤りが積み重なる。今日のエージェントは補助としては強力だが、完全に任せきる本番運用にはまだ時間がかかる、と冷静だ。

[The Rise of AI-Native Software Engineering](https://arxiv.org/abs/2606.12986) 📖
48本の研究をまとめた総説。決まった小さなタスクでは開発が速くなる一方、慎重さが要る場面では生成物のかなりの割合（およそ4割）に脆弱性が見つかり、使う人は増えても信頼はむしろ下がる。だからこそ、意図を明確に伝え、批判的に評価し、責任を持って確かめる「判断力」が、人間側の強みになる、と締める。

[Skills for the future software profession: beyond agentic AI!](https://arxiv.org/abs/2606.21894)
研究者・実務家の議論から、将来の技術者に要る力を3つ挙げる——要求を機械で検証できる形に書く力、エージェント群をまとめる力、組織の理解が失われるのを防ぐ力。ここでも「手作業のレビューは、もう当てにできる安全装置ではない」と結論する。

### 地に足のついた改善

[TMax: A Simple Recipe for Terminal Agents](https://arxiv.org/abs/2606.23321)
長い作業を安定して学習させるのは難しい。TMax は練習環境を大量に自動生成し、学習を安定させる工夫を重ねた。小型モデルでも端末操作のベンチマークで同規模の公開モデル中で最高、SWE-bench でも1割ほど底上げした。派手な新モデルでなくても、データと学習の地道な工夫で伸ばせる。

![TMax](../assets/2606.23321-tmax-pipeline.png)
> 図（TMax）：いくつもの軸から組み合わせて、練習環境を大量に自動生成する流れ。（[論文](https://arxiv.org/abs/2606.23321)）

[Socratic-SWE: Self-Evolving Coding Agents via Trace-Derived Agent Skills](https://arxiv.org/abs/2606.07412)
自分の解いた記録を教材に変えて、賢くなり続ける。過去の記録から「よくある失敗と有効な直し方」をスキルとして貯め、それで練習問題を自動生成し、解いて、また記録を増やす。この循環で、追加の人手なしに成績を上げた。ただし決まった題材の中で回すため、スキルが充実すると新しい学びが枯れてくる、と限界も述べる。

[LLM Agents Can See Code Repositories（SeeRepo）](https://arxiv.org/abs/2606.14061)
コードの構造を図（画像）として見せたら賢くなるか。答えは「使い方次第」。図だけだと逆に精度が落ちて費用も増えるが、テキストに図を添えると費用が下がり精度もわずかに上がる。特に「どこを直すか探す」場面で効いた。図は万能薬ではなく、テキストの補助として効く（Python での検証）。

![SeeRepo](../assets/2606.14061-seerepo-overview.png)
> 図（SeeRepo）：コードの依存関係を図にしてテキストに添える設計と、その主な知見の概観。（[論文](https://arxiv.org/abs/2606.14061)）

[FastContext: Training Efficient Repository Explorer for Coding Agents](https://arxiv.org/abs/2606.14066)
「コードを探す作業」と「問題を解く作業」を分け、探すほうを小型の専門の助手に任せる。助手は必要なファイルと行だけを手早く返す。正答を上げつつ費用（トークン）を大きく下げた。分業で、余計な文脈で汚すのを防ぐ設計だ。※知財の都合で取り下げられており、検証は限定的。

## この号のまとめ
- **確かなこと**：委譲への移行は実データで裏づく（Codex）。ボトルネックは「書くこと」でなく「確かめること」に移った（AI-Native SE・Skills・Agentic Software が別々に指摘）。
- **今月はっきりした壁**：長い連続開発での崩れ。短いベンチマークの高得点をそのまま信じない。
- **1本のみで要追試**：独立課題では8割超が、長い開発で4割弱に崩れる（Agentic Software、1つの観測。ただし「確かめるのが壁」という複数論文とは整合的）／探索を分業して速く安く（FastContext、1研究・取り下げ）。

## 次に読みたくなる問い
- 長い連続開発を測る評価と、状態管理・検証・やり直しを組み込んだ仕組み（[harness](../../architecture/harness.md)）。
- 機械で検証できる仕様と、安全なコード生成。
- 委譲を支える運用の基盤——並行するエージェントの監督と承認（[agentops](../../operations/agentops.md)・[human-ai](../../operations/human-ai.md)）。
