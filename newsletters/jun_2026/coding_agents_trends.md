# Coding Agents 研究トレンド（2026年6月）

> 対象：[coding-agents](../../applications/system/coding-agents.md) の 2026年6月論文（8本）。各論文の arXiv HTML 本文（1本のみ abstract）を精読してまとめた。

## まず、この分野を一言で

コーディングエージェントとは、**AI が実際にソフトウェアを書く**取り組みだ。バグを直し、テストを書き、コードを設計する。ここは「AI の能力がどこまで伸びたか」と「実際の開発で使いものになるか」が**同時に露わになる最前線**である。

6月の8本は、大きく2つの層に分かれる。ひとつは、働き方そのものの変化を扱う**大きな絵**——人が AI に仕事を"任せる（委譲する）"方向へ移り、人の役割は「作る人」から「設計し・監督する人」へ動いている。もうひとつは、エージェントを**具体的に強く・安くする工夫**だ。

そして両方に共通して、ある壁が浮かび上がった。**"1問なら解けるのに、長い開発になると崩れる"**という壁と、**"生成は速いが、検証（レビュー）が追いつかない"**という壁である。

## 今月の3つの流れ

**流れ①：会話から"委譲"へ（複数論文で共通）**
利用実態のデータ（Codex）が、はっきり示した。半日がかりの仕事を AI に任せる割合が半年で **2.1% → 25.6%** と10倍以上に増え、ユーザーの **28.6% が同時に5つ以上のエージェントを動かす**。もはや「AI と会話する」のではなく「**複数のエージェントを部下のように運用する**」段階だ。Agentic Software（"サービスとしてのエージェント"論）や、将来の技能を論じた Skills 論文も、同じ方向を別角度から支持する。

**流れ②：壁は"連続実行"と"検証"（今月はっきりした点）**
ただし、任せきれない理由も同じくらい明確になった。1つの独立した問題なら8割超解けるのに、**長く続く実際の開発では成功率が最大38%まで崩れる**（Agentic Software）。生成されたコードの**約4割に脆弱性**があり、使う人は増えても信頼はむしろ下がる（AI-Native SE）。「**手作業のレビューは、もう当てにできる安全装置ではない**」（Skills 論文）。ボトルネックはコードを書くことではなく、**書いたものを検証すること**へ移った。

**流れ③：地に足のついた改善——強く、安く（具体的な工夫）**
派手さはないが実利のある研究も並んだ。学習の工夫で小型モデルの実力を底上げし（TMax）、自分の失敗から学んで賢くなり（Socratic-SWE）、必要な文脈だけを絞ることで費用を下げる（SeeRepo・FastContext）。

> ※数字は各論文の HTML 本文より。単発（1論文のみ）の目を引く結果は末尾に「要追試」として分けた。

## 論文紹介（テーマ別）

### ① 大きな絵：委譲への移行と、その壁

[The Shift to Agentic AI: Evidence from Codex](https://arxiv.org/abs/2606.26959)
実際の利用データから「働き方がどう変わったか」を測った。半年で週次利用が5倍を超え、**半日相当の仕事を任せる割合が 2.1% → 25.6%**、ユーザーの **28.6% が同時に5つ以上のエージェント**を動かす。つまり「相談する AI」から「**任せる AI**」へ。生産性を活かす鍵は、モデルの賢さより**委譲・監督・作業の割り振りといった"運用"の設計**だ、と結論する（最先端環境ゆえ一般化には注意）。

![Evidence from Codex](../assets/2606.26959-codex-adoption.png)
> 図（Evidence from Codex）：ユーザー種別ごとの利用の伸び。会話から委譲への移行が見て取れる。（[論文](https://arxiv.org/abs/2606.26959)）

[Agentic Software: How AI Agents Are Restructuring the Software Paradigm](https://arxiv.org/abs/2606.05608)
ソフトウェアの作り方が「あらかじめ人が全部書く」から「AI が実行時に判断して作る」へ移る、と論じる。だが核心は警告にある——**1つの独立した課題では80%超だった成功率が、長く続く開発では38%まで崩落**する。文脈がずれ、誤りが積み重なり、"技術的負債"がたまる。今日のエージェントは**補助としては強力だが、完全自律の本番運用にはまだ数年かかる**、と冷静だ。

[The Rise of AI-Native Software Engineering](https://arxiv.org/abs/2606.12986) 📖
48本の研究を統合した総説。有界なタスクでは開発が **+55.8%** 速くなる一方、機微な場面では**生成物の約4割に脆弱性**が見つかり、採用は増えても**信頼はむしろ下がる**。「流暢な出力が"できたつもり"の錯覚を生む」。だからこそ、**意図を明確に伝え、批判的に評価し、責任を持って検証する"判断力"**が、人間側の差別化能力になる、と締める。

[Skills for the future software profession: beyond agentic AI!](https://arxiv.org/abs/2606.21894)
研究者・実務家の議論から、将来の技術者に要る3つの力を挙げる——**要求を機械が検証できる形に書く力／エージェント群をまとめる力／組織の理解が失われる"認知的負債"を管理する力**。ここでも結論は同じ方向を指す：「開発者は AI のコードを吟味せず受け入れがちで、**手作業のレビューは当てにできる安全装置ではない**」。

### ② 地に足のついた改善

[TMax: A Simple Recipe for Terminal Agents](https://arxiv.org/abs/2606.23321)
なぜ効くのか——長い作業を安定して学習させるのは難しい。TMax は**14,600個の練習環境を自動生成**し、訓練を安定させる工夫を重ねた。結果、小型モデルが端末操作ベンチで同規模の公開モデル最高、**SWE-bench も 44% → 53.5%**。派手な新モデルでなくとも、データと訓練の地道な工夫で底上げできることを示す。

![TMax](../assets/2606.23321-tmax-pipeline.png)
> 図（TMax）：9つの軸から組み合わせて 14,600 個の練習環境を自動生成するパイプライン。（[論文](https://arxiv.org/abs/2606.23321)）

[Socratic-SWE: Self-Evolving Coding Agents via Trace-Derived Agent Skills](https://arxiv.org/abs/2606.07412)
自分の解いた記録を教材に変えて、賢くなり続ける。過去の記録から「よくある失敗と有効な直し方」をスキルとして貯め、それを使って練習問題を自動生成し、解いて、また記録を増やす。この循環で **SWE-bench 50.4%（+8pt）** を、追加の人手なしに達成。ただし固定した題材の中で回すため、スキルが充実すると新しい学びが枯れてくる、と限界も述べる。

[LLM Agents Can See Code Repositories（SeeRepo）](https://arxiv.org/abs/2606.14061)
コードの構造を**図（画像）として見せたら賢くなるか**を検証した。答えは「使い方次第」。**図だけ**だと逆に精度が落ちて費用も跳ねるが、**テキストに図を添える**と GPT-5-mini で費用 **−26%**・精度わずかに向上。特に「どこを直すか探す」場面で効いた。図は万能薬ではなく、テキストの補助として効く（Python での検証）。

![SeeRepo](../assets/2606.14061-seerepo-overview.png)
> 図（SeeRepo）：コードの依存関係を図にしてテキストに添える設計と、その主要な知見の概観。（[論文](https://arxiv.org/abs/2606.14061)）

[FastContext: Training Efficient Repository Explorer for Coding Agents](https://arxiv.org/abs/2606.14066)
「コードを探す作業」と「問題を解く作業」を分け、**探す方を小型の専門助手に任せる**。助手は必要なファイルと行だけを手早く返す。結果、正答 **+5.5%**・費用（トークン）**−60%**。分業で無駄な文脈汚染を防ぐ設計だ。※知財の都合で取り下げられており、主張の検証は限定的。

## この号のまとめ（何が確かで、何がまだ怪しいか）

- **確かなこと**：委譲への移行は実データで裏づく（Codex）。ボトルネックは「書くこと」でなく「**検証すること**」に移った（AI-Native SE／Skills／Agentic Software が別々に指摘）。
- **今月はっきりした壁**：**長い連続開発での崩れ**。短いベンチの高得点をそのまま信じない。
- **単発だが面白い（要追試）**：独立課題80%超→連続38%の"崖"（Agentic Software、1つの観測。ただし"検証が壁"という複数論文と整合）／探索の分業で性能↑費用↓（FastContext、1研究・取り下げ）。

## 次に読みたくなる問い
- **長い連続開発**を測る評価と、状態管理・検証・やり直しを組み込んだ段取り（[harness](../../architecture/harness.md)）。
- **機械が検証できる仕様**と、安全なコード生成。
- **委譲の運用基盤**——並行するエージェントの監督と承認（[agentops](../../operations/agentops.md)・[human-ai](../../operations/human-ai.md)）。
