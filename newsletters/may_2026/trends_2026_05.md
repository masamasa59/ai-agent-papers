## エグゼクティブサマリー

今期のエージェント研究は、次の **4本の太い柱** に収束しつつある。

1. **Skill / Harness を一級市民として扱う設計学の成立**
   Anthropic Skills, MCP, Agent Harness といった「モデルの外側にある実行基盤」が、研究コミュニティでも本格的に独立した研究対象として確立。`A Comprehensive Survey on Agent Skills`（[paper](https://arxiv.org/abs/2605.07358)）が分類学を提示し、`SkillOS`・`SkillsVote`・`SkillScope`・`SkillGenBench`・`SkillFlow`・`HEAVYSKILL`・`Counterfactual Trace Auditing` 等、Skill関連だけで10本以上が同時期に出現した。これは、3月までの「タスク特化スキル提案」段階から「**ライフサイクル全体の統治**」段階への移行を示す。

2. **Self-Evolving Agents の "実用化" 段階**
   Self-evolution研究は概念検証から「**メモリ・スキル・ワークフローを統合的に進化させる運用システム**」へ移行。`EvoMemBench`・`EVOLVEMEM`・`Ratchet`・`GraphMind`・`EXG` 等が、進化の "下水道" にあたる**衛生（hygiene）・整合性・監査性**を主題化している。`Ratchet: A Minimal Hygiene Recipe for Self-Evolving LLM Agents`（[paper](https://arxiv.org/abs/2605.22148)）というタイトル自体が、コミュニティの関心が「最大化」から「最小限の衛生保証」へ移ったことを象徴する。

3. **Cybersecurity Agents の本格参入**
   攻撃・防御の両方でエージェントが現実のCTF・ペンテスト・脆弱性修復タスクに入る。`Cochise: A Reference Harness for Autonomous Penetration Testing`（[paper](https://arxiv.org/abs/2605.11671)）が参照実装を提示し、`ExploitBench`（[paper](https://arxiv.org/abs/2605.14153)）が能力ラダーを定義、`MemRepair`（[paper](https://arxiv.org/abs/2605.17444)）・`Root-Cause-Driven Automated Vulnerability Repair`（[paper](https://arxiv.org/abs/2605.04251)）が防御側を埋める。4月のCybersecurityニュースレター（[link](../apr_2026/cybersecurity_2025.md)）で予測した「攻防の同時産業化」が現実化している。

4. **長期記憶・長期コンテキスト・長期タスクの "腐敗" 問題**
   `Useful Memories Become Faulty When Continuously Updated by LLMs`（[paper](https://arxiv.org/abs/2605.12978)）、`STALE: Can LLM Agents Know When Their Memories Are No Longer Valid?`（[paper](https://arxiv.org/abs/2605.06527)）、`Rethinking How to Remember: Beyond Atomic Facts`（[paper](https://arxiv.org/abs/2605.19952)）等、**長期運用で記憶が壊れる**ことを正面から扱う論文が複数同時に出た。これは2025年までの「memory == more is better」論調からの明確な転換点であり、4月の `Contextual Agentic Memory is a Memo, Not True Memory`（[paper](https://arxiv.org/abs/2604.27707)）の問題提起への実証的応答とも読める。

共通する未解決課題は次の3点に集約される:
1. **長期運用における腐敗（メモリ・スキル・ワークフロー）の検出と修復**
2. **「失敗帰属（failure attribution）」の構造化**（誰の・何が悪かったかを特定する仕組み）
3. **行動評価では捉えられない安全特性の保証**（`Position: Behavioural Assurance Cannot Verify the Safety Claims Governance Now Demands` ([paper](https://arxiv.org/abs/2605.15164)) が正面から問題化）

## 1. Skills 研究の独立宣言

### 1.1 このジャンルのトレンドと課題感

🔍 2024年までのエージェント研究は **(a) ツール呼び出し** と **(b) ワークフロー設計** が主な議論軸だった。Anthropic が2025年末に提唱した「Agent Skills」（モデル外に置く、起動条件付きの再利用可能な手順書/コード片）は、当初は工学的実装の話題として扱われていた。しかし4月の `Agent Skills: A Data-Driven Analysis of Claude Skills`（2602.08004）・`SoK: Agentic Skills`（2602.20867）等を経て、5月には **生成・キュレーション・監査・赤チーム化・ユーザビリティ・分類学** という研究分野としての全構成要素が同時並行で立ち上がった。残課題は、**スキル流通の標準化**（OCI Registry的なもの）と**進化過程の安全性保証**である。

### 1.2 スキルの分類学・サーベイ

#### [May 2026] "A Comprehensive Survey on Agent Skills: Taxonomy, Techniques, and Applications" [[paper](https://arxiv.org/abs/2605.07358)] 📖

- **概要（推定）**: Agent Skills を**取得・表現・選択・実行・更新**の5段階に分解し、各段階の代表手法を整理する包括サーベイ。2月の `Agent Skills for Large Language Models: Architecture, Acquisition, Security, and the Path Forward`（2602.12430）が初の体系的整理だったのに対し、3ヶ月後の本サーベイは Application 寄りの分類軸を加えている可能性が高い。
- **差分・新規性（推定）**: 既存のツール使用サーベイ（3月の `The Evolution of Tool Use in LLM Agents`(2603.22862)）が「ツール呼び出しの進化」を縦軸に整理していたのに対し、本サーベイは「**スキルというアーティファクト**」を中心に据え、`SkillsVote`(下記) や `SkillScope`(下記) のような統治・権限論文を結節点として位置づけたと考えられる。

#### [May 2026] "HEAVYSKILL: Heavy Thinking as the Inner Skill in Agentic Harness" [[paper](https://arxiv.org/abs/2605.02396)]

- **概要（推定）**: 推論（thinking）自体を「内側のスキル」として明示的にハーネス上で扱うアプローチ。タイトルから察するに、O1系の chain-of-thought や reasoning model の `<thinking>` ブロックを、外部スキル（ツール、ハーネス補助）と同等の **ファーストクラスの呼び出し可能ユニット** として扱う設計。
- **差分・新規性（推定）**: 既存のスキル研究は「外部ツールの抽象化」がほとんどだったのに対し、**推論プロセスそのものをスキルとして扱う**点が新しい。これにより、推論コストの予算管理、推論ステップの再利用、スキル粒度での評価が可能になる。`Tools as Continuous Flow for Evolving Agentic Reasoning`([paper](https://arxiv.org/abs/2605.07339)) と思想的に近い。

### 1.3 スキルの生成と評価

#### [May 2026] "SkillGenBench: Benchmarking Skill Generation Pipelines for LLM Agents" [[paper](https://arxiv.org/abs/2605.18693)] ⚖️

- **概要（推定）**: スキル生成パイプラインそのものを評価対象とするベンチマーク。生成された個別スキルの性能ではなく、**「同じユースケースに対して、どの生成パイプラインがより良いスキル群を作るか」** を測定する meta-benchmark。
- **差分・新規性（推定）**: 4月の `SKILLFLOW: Benchmarking Lifelong Skill Discovery and Evolution`(2604.17308) が「発見・進化」を測ったのに対し、本ベンチは「**生成パイプライン**」の品質を測る一段上のメタ評価。`FrontierSmith: Synthesizing Open-Ended Coding Problems at Scale`([paper](https://arxiv.org/abs/2605.14445)) と同様、データ/スキル合成の品質競争が始まったことを示す。

#### [May 2026] "SkillFlow: Flow-Driven Recursive Skill Evolution for Agentic Orchestration" [[paper](https://arxiv.org/abs/2605.14089)]

- **概要（推定）**: スキル進化を「フロー」として再帰的に駆動するオーケストレーション機構。タイトルから察するに、複数スキルの実行結果が次のスキル進化を再帰的に誘発する設計。
- **差分・新規性（推定）**: 既存の `SkillClaw`(2604.08377) や `SkillX`(2604.04804) が「スキルを発見・蓄積」する静的視点だったのに対し、**スキル間の連鎖が進化フローを形成する** 動的視点。再帰的最適化という意味で、Multi-Agentセクションの `Recursive Agent Optimization`([paper](https://arxiv.org/abs/2605.06639)) と通底する。

### 1.4 スキルのキュレーション・ライフサイクル

#### [May 2026] "SkillOS: Learning Skill Curation for Self-Evolving Agents" [[paper](https://arxiv.org/abs/2605.06614)]

- **概要（推定）**: 進化過程で**どのスキルを残し、どれを捨てるか**を学習するキュレーション機構。OSという命名から察するに、スキルのプロセス管理（生成・実行・休止・廃棄）を抽象化したフレームワーク。
- **差分・新規性（推定）**: 4月の `Co-Evolving LLM Decision and Skill Bank Agents`(2604.20987) がスキルバンクの共進化を扱ったが、本研究は**負のスキル（性能を下げるもの）の検出と除去**を主題化していると推定される。`Useful Memories Become Faulty`([paper](https://arxiv.org/abs/2605.12978)) のスキル版とも言える問題提起。

#### [May 2026] "SkillsVote: Lifecycle Governance of Agent Skills from Collection, Recommendation to Evolution" [[paper](https://arxiv.org/abs/2605.18401)]

- **概要（推定）**: スキル収集→推薦→進化までのライフサイクル全体をガバナンスする投票（vote）ベースの仕組み。複数の評価軸（性能・安全性・コスト）からスキル採用を多数決的に決定。
- **差分・新規性（推定）**: 単一の評価メトリクスではなく、**ガバナンス的合意形成**をスキル採用判断に持ち込んだ点が新しい。エンタープライズ運用の `Governance by Construction for Generalist Agents`([paper](https://arxiv.org/abs/2605.20874)) と思想を共有する。

### 1.5 スキルの権限・セキュリティ

#### [May 2026] "SkillScope: Toward Fine-Grained Least-Privilege Enforcement for Agent Skills" [[paper](https://arxiv.org/abs/2605.05868)]

- **概要（推定）**: スキル実行時に最小権限原則（least-privilege）を細粒度で強制する仕組み。各スキルが要求するリソース・APIアクセスを宣言的に管理し、必要最小限のみ許可。
- **差分・新規性（推定）**: 従来のRBAC的な役割ベース管理ではなく、**スキル単位の宣言型権限**という新しい粒度を提示。Cybersecurity セクションの `Trust No Tool`([paper](https://arxiv.org/abs/2605.17453)) と思想を共有し、「**スキル自体が攻撃ベクタになりうる**」前提を運用に持ち込む。

#### [May 2026] "Counterfactual Trace Auditing of LLM Agent Skills" [[paper](https://arxiv.org/abs/2605.11946)]

- **概要（推定）**: スキル実行トレースに対し「**もしこのスキルが呼ばれなかったら**」の counterfactual を生成し、スキルの実際の貢献度を監査する手法。
- **差分・新規性（推定）**: 既存のトレース監査は「何が起きたか」の記録にとどまっていたのに対し、本研究は**因果的反事実推論**を持ち込む点で一歩進んでいる。Multi-Agentセクションで議論される **失敗帰属（failure attribution）** の核心技術として、今後広く参照される可能性。

### 1.6 スキルの赤チーム化とユーザビリティ

#### [May 2026] "Proteus: A Self-Evolving Red Team for Agent Skill Ecosystems"

- **概要（推定）**: スキル生態系に対する**自己進化型レッドチーム**。タイトルから察するに、攻撃側エージェントが防御側スキルの進化に応じて自らも進化する敵対的共進化（co-evolution）設定。
- **差分・新規性（推定）**: 静的なレッドチームではなく、**スキル進化と同期して進化する攻撃エージェント**を持ち込んだ点が新しい。4月の `Red Skills or Blue Skills?`(2604.13064) のスキル流通分析を、攻撃側からの進化シミュレーションに発展させたものと推定される。

#### [May 2026] "Toward User Comprehension Supports for LLM Agent Skill Specifications"

- **概要（推定）**: スキル仕様（specification）を**エンドユーザ/オペレータが理解可能な形式**で提示するためのUX研究。
- **差分・新規性（推定）**: 技術指向のスキル研究の中で、**ユーザ理解可能性**を主題化した珍しい論文。エンタープライズ採用フェーズでは「**エンジニアではない管理者がスキルを承認できるか**」が現実問題となるため、`SkillsVote` のガバナンス論と補完関係にある。

### 1.7 横断的示唆

スキル研究の急速な分化は、ソフトウェア工学における「**パッケージ管理の歴史**」をなぞっている。
- **生成** → npmやpipのようなパッケージ
- **キュレーション** → リポジトリのメンテナンス
- **権限・セキュリティ** → サンドボックス・最小権限
- **赤チーム** → サプライチェーン攻撃対策
- **ユーザ理解** → README/docs

実装者向けのTipsとして:
1. スキルは**バージョン管理可能なアーティファクト**として扱う（`Code as Agent Harness` [paper](https://arxiv.org/abs/2605.18747) の発想）。
2. **トリガー条件と権限を仕様レベルで明示**する（`SkillScope`の示唆）。
3. **使用トレースを全保存**し、後で counterfactual 監査が可能な状態にする（`Counterfactual Trace Auditing`）。
4. **赤チーム化を運用に組み込む**（`Proteus`の示唆）。CI/CDの一部としてレッドチームを回す設計。

## 2. Self-Evolution: 「進化させる」から「進化を統治する」へ

### 2.1 このジャンルのトレンドと課題感

🔍 2025年Q4〜2026年Q1の進化エージェント研究は「**もっと進化させる**」競争だった。Yunjue Agent Tech Report(2601.18226)、ASI-Evolve(2603.29640)、CORAL(2604.01658) など、大規模・無制限の自己進化が次々に提案された。今期は **「進化の副作用を制御する」** 方向に明確にシフトしている。具体的には、(1) **進化の発散と停滞の制御**、(2) **メモリ/スキル/ワークフローの統合的進化**、(3) **進化過程の可観測性と監査** の3軸。残課題は、**進化の収束条件と評価フレームワーク**である。

### 2.2 進化の衛生（Hygiene）

#### [May 2026] "Ratchet: A Minimal Hygiene Recipe for Self-Evolving LLM Agents" [[paper](https://arxiv.org/abs/2605.22148)]

- **概要（推定）**: 自己進化型エージェントに最小限の「衛生（hygiene）」を導入するための実践レシピ。「ラチェット（一方向締め付け）」という命名から、**進化を後戻りさせない最小限の制約**（不変条件の保護、退化検出、保守的ロールバック）を提供する設計と推定。
- **差分・新規性（推定）**: 既存の自己進化研究が「進化能力の上限」を競っていたのに対し、本研究は **「進化の下限保証」** を提案する。これは、`Useful Memories Become Faulty`([paper](https://arxiv.org/abs/2605.12978)) や `Large Language Model Agents Are Not Always Faithful Self-Evolvers`(2601.22436) で示された「進化の暴走」リスクへの実装側からの応答。今後の self-evolving agent デプロイの**事実上の必須コンポーネント**になる可能性。

### 2.3 進化過程の評価

#### [May 2026] "EvoMemBench: Benchmarking Agent Memory from a Self-Evolving Perspective" [[paper](https://arxiv.org/abs/2605.18421)] ⚖️

- **概要（推定）**: メモリ自体ではなく**メモリの進化過程**を評価するベンチマーク。タイトルから、(1) 進化前後の性能差、(2) 進化過程での退化検出、(3) 進化結果の安定性 を主要メトリクスとすると推定される。
- **差分・新規性（推定）**: 4月の `SEA-Eval: A Benchmark for Evaluating Self-Evolving Agents Beyond Episodic Assessment`(2604.08988) がエピソード評価の限界を超える評価フレームワークを提案したのに対し、本ベンチはメモリに焦点を絞ったドメイン特化版。`HORIZONBENCH`(2604.17283) と並んで、**時間軸を含む評価**の標準化に貢献する。

### 2.4 進化アーキテクチャの多様化

#### [May 2026] "EVOLVEMEM: Self-Evolving Memory Architecture via AutoResearch for LLM Agents" [[paper](https://arxiv.org/abs/2605.13941)]

- **概要（推定）**: メモリ**アーキテクチャ自体**を AutoResearch（自動研究）で進化させる。つまり、特定のメモリ構造を進化させるのではなく、メモリ機構の設計を探索する meta-level な進化。
- **差分・新規性（推定）**: 4月の `MemEvolve: Meta-Evolution of Agent Memory Systems`(2512.18746) と方向性は近いが、AutoResearch（科学発見エージェント）を駆動装置として使う点が独自。Research Agents セクションの `Agentic Discovery of Neural Architectures: AIRA-Compose and AIRA-Design`([paper](https://arxiv.org/abs/2605.15871)) と思想を共有する「**設計探索のエージェント化**」潮流の一部。

#### [May 2026] "EXG: Self-Evolving Agents with Experience Graphs"

- **概要（推定）**: 経験を**グラフ構造**として蓄積し、グラフ操作によって進化を駆動するアーキテクチャ。`Trajectory-Informed Memory Generation`(2603.10600) の流れを汲み、**経験間の関係性**を一級市民として扱う。
- **差分・新規性（推定）**: 既存の経験ベース進化はリストやベクトル空間で経験を扱っていたが、**経験間の因果・類似・対比関係**をグラフで明示する点が新しい。`GraphMind`(下記)とは姉妹研究的な位置づけ。

#### [May 2026] "GraphMind: From Operational Traces to Self-Evolving Workflow Automation"

- **概要（推定）**: 運用トレース（実際の業務実行ログ）から**ワークフロー自動化**を自己進化的に学習する。EXGがエージェント内部の経験を扱うのに対し、本研究は組織レベルの運用トレースを対象。
- **差分・新規性（推定）**: 2月の `AORCHESTRA: Automating Sub-Agent Creation for Agentic Orchestration`(2602.03786) が「ゼロから自動化を作る」のに対し、本研究は **「既存の運用ログから自動化を進化させる」** ボトムアップアプローチ。エンタープライズ採用に即した方向性。

### 2.5 自己進化型検索の出現

#### [May 2026] "Towards Self-Evolving Agentic Literature Retrieval" [[paper](https://arxiv.org/abs/2605.14306)]

- **概要（推定）**: 文献検索エージェントが**検索戦略自体を経験から進化させる**。Deep Research セクションでも触れたが、Self-Evolution の文脈では「特定タスクへの最適化が進化として現れる初の例」として位置づけられる。
- **差分・新規性（推定）**: 既存の Deep Research 研究は静的な検索戦略を持っていたが、本研究は**ユーザの過去クエリ・成功失敗から検索戦略を適応的に進化**させる。Skills の `SkillFlow`([paper](https://arxiv.org/abs/2605.14089)) と同様、**動的フローによる進化**の流れの一部。

### 2.6 横断的示唆

Self-Evolution の今期の動向は **「能力の最大化」から「進化の信頼性」** への移行。実装者向けTipsとして:

1. **進化の前後で不変条件をテスト**する仕組みを必ず入れる（`Ratchet`の発想）。これはCI/CDの test suite に相当する役割。
2. **退化（regression）の検出**を独立した監視として実装。ベンチマーク数値の単純比較では不十分。
3. **進化結果の可説明性**を保つため、`Counterfactual Trace Auditing`([paper](https://arxiv.org/abs/2605.11946)) のような因果監査を組み込む。
4. **AutoResearch駆動の進化**(`EVOLVEMEM`の発想) は強力だが、**探索空間の制約**が安全性の鍵。

## 3. メモリ研究の二極化：楽観と幻滅

### 3.1 このジャンルのトレンドと課題感

🔍 4月のメモリ研究は「**現状のメモリは記憶ではなくメモ（memo）に過ぎない**」という根源的問題提起（`Contextual Agentic Memory is a Memo, Not True Memory`、2604.27707）で締めくくられた。5月はこの問題提起への**実証的応答**が次々に出る形となった。今期のメモリ論文は明確に **(A) 楽観派**（より大きく、より統合的なメモリを作る）と **(B) 悲観派**（メモリの妥当性・腐敗を疑う）に二極化している。残課題は、両派の知見をどう統合した運用設計に落とすか。

### 3.2 悲観派：メモリ腐敗の発見

#### [May 2026] "Useful Memories Become Faulty When Continuously Updated by LLMs" [[paper](https://arxiv.org/abs/2605.12978)] 🔥

- **概要（推定）**: LLMによるメモリの連続更新が、**もともと有用だった記憶を逆に破損させる**現象を実証。タイトル自体が結論であり、おそらく複数ドメインで「**メモリ更新パイプラインが時間とともに性能を下げる**」ことを示すケーススタディ集。
- **差分・新規性（推定）**: メモリ研究はこれまで「より良く更新する」競争だったが、本研究は **「そもそも更新すべきでない場面がある」** という反論を提示する。1月の `Large Language Model Agents Are Not Always Faithful Self-Evolvers`(2601.22436) のメモリ版とも言える。今後、メモリ更新パイプラインの設計には**改竄検出層**を必ず入れる流れになると予想される。

#### [May 2026] "STALE: Can LLM Agents Know When Their Memories Are No Longer Valid?" [[paper](https://arxiv.org/abs/2605.06527)] ⚖️

- **概要**: 過去のやり取りをメモリバンクに蓄積するLLMエージェントが、**自身のメモリが陳腐化（stale）したことを認識できるか** を400件の競合シナリオで評価するベンチマーク。著者: Hanxiang Chao, Yihan Bai, Rui Sheng, Tianle Li, Yushi Sun。
- **差分・新規性**: 「メモリの正しさ」ではなく「**メモリの妥当性ウィンドウの認識**」を測る初のベンチマーク。`Useful Memories Become Faulty`([paper](https://arxiv.org/abs/2605.12978)) で示された問題に対する**評価インフラ**を提供。今後のメモリ設計では「いつまで有効か」を明示する `valid_until` フィールドが事実上の標準になる可能性。

#### [May 2026] "Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory" [[paper](https://arxiv.org/abs/2605.19952)]

- **概要（推定）**: 既存のメモリ表現が「**原子的事実（atomic facts）**」（"Aは Bである"形式）に依存することの限界を指摘し、より構造化された表現を提案。
- **差分・新規性（推定）**: 4月の `To Know is to Construct: Schema-Constrained Generation for Agent Memory`(2604.20117) が**スキーマ制約**で表現問題に対処したのに対し、本研究は**原子的事実モデル**自体を疑う一段深い問題提起。`Contextual Agentic Memory is a Memo`(2604.27707) のポジションペーパーへの建設的応答とも読める。

### 3.3 楽観派：メモリ能力の拡張

#### [May 2026] "MEMO: Memory as a Model" [[paper](https://arxiv.org/abs/2605.15156)]

- **概要（推定）**: メモリそのものを**独立したモデル**として扱い、学習・推論可能な構造として定式化。タイトルから、メモリを単なるストレージではなく**学習可能なパラメトリック構造**として実装すると推定される。
- **差分・新規性（推定）**: 既存のRAG/ベクタDBが non-parametric なメモリだったのに対し、本研究は **メモリのパラメトリック化**を提案。`Contextual Agentic Memory is a Memo`(2604.27707) で指摘された「**重みベース統合の欠如**」への直接的応答と言える。長期的には、現在の RAG パイプラインを置き換える可能性がある。

#### [May 2026] "MEMGYM: a Long-Horizon Memory Environment for LLM Agents" [[paper](https://arxiv.org/abs/2605.20833)] ⚖️

- **概要（推定）**: 長期記憶を要する**訓練・評価環境**。OpenAI Gym のメモリ版という命名から、強化学習的なエピソード反復で長期記憶能力を鍛える環境と推定。
- **差分・新規性（推定）**: 既存のメモリベンチマーク（LoCoMo, LongDialQA）が静的な評価だったのに対し、本環境は **エージェントが環境と相互作用しながらメモリを構築する**動的な訓練・評価が可能。Research Agents セクションの `NanoResearch`([paper](https://arxiv.org/abs/2605.10813)) のような個別ユーザ向け研究で、訓練源として使われる可能性。

#### [May 2026] "Auto-Dreamer: Learning Offline Memory Consolidation for Language Agents" [[paper](https://arxiv.org/abs/2605.20616)]

- **概要（推定）**: オフラインで **メモリの統合（consolidation）** を学習する手法。神経科学の「睡眠中の記憶統合」をアナロジーに、エージェントの "休息時間" にメモリを整理・統合する仕組み。
- **差分・新規性（推定）**: 4月の `Artifacts as Memory Beyond the Agent Boundary`(2604.08756) が状況的認知の視点だったのに対し、本研究は**神経科学的二層モデル**（海馬→新皮質）に直接訴える。`Contextual Agentic Memory is a Memo`(2604.27707) で言及された「**遅い大脳新皮質の重み統合**」を実装した初の試みとも言える。

#### [May 2026] "Tree-based Credit Assignment for Multi-Agent Memory System" [[paper](https://arxiv.org/abs/2605.04811)]

- **概要（推定）**: マルチエージェント環境において、ツリー構造を使って**どのエージェントの記憶が結果に寄与したか**の credit assignment を行う。
- **差分・新規性（推定）**: マルチエージェントの failure attribution 問題（`Beyond Individual Intelligence`([paper](https://arxiv.org/abs/2605.14892)) サーベイで主題化）の**メモリ版**。複数エージェントが共有・参照するメモリの**因果的貢献度**を測定可能にする。

#### [May 2026] "When Continual Learning Moves to Memory: A Study of Experience Reuse in LLM Agents" [[paper](https://arxiv.org/abs/2604.27003)]

- **概要（推定）**: 継続学習（continual learning）を**重みの更新ではなくメモリの蓄積**で実現する方向性を実証研究として整理。
- **差分・新規性（推定）**: 「重み更新 vs メモリ蓄積」のトレードオフは長年の論点だが、本研究は **LLM時代における経験再利用**という新しい視点で再整理する。`MEMO: Memory as a Model`([paper](https://arxiv.org/abs/2605.15156)) と思想的に近いが、よりempiricalな実証寄り。

### 3.4 横断的示唆: メモリ設計の "新しい標準"

楽観派と悲観派の両方を統合した実装パターンは次の通り:

1. **append-only + supersedes リレーション**: メモリの上書きは禁止し、新レコードで「旧レコードを置き換える」と宣言する。`Useful Memories Become Faulty` の警告への対策。
2. **`valid_until` を明示**: 全メモリレコードに妥当性ウィンドウを付ける。`STALE` のベンチに対応するため。
3. **取り出し時に "stale check"**: メモリを使う前に妥当性確認をルーチン化。
4. **オフライン consolidation pass**: `Auto-Dreamer` の発想で、定期的にメモリを整理・統合する batch job。
5. **構造化された表現**: 原子的事実だけでなく、`Rethinking How to Remember` の示唆通り、関係性・抽象度を持つ表現を併用。
6. **メモリをモデルとして扱う**(`MEMO` の発想): 長期的にはパラメトリックメモリへの移行を計画。

### 3.5 1月→4月→5月のメモリ研究の流れ


## 4. Cybersecurity Agents の本格参入

### 4.1 このジャンルのトレンドと課題感

🔍 4月号のサイバーセキュリティニュースレター（[link](../apr_2026/cybersecurity_2025.md)）では「**攻撃の永続化**」「**防御のレイヤ分化**」「**ベンチマーク群の急成立**」の3軸を整理した。5月はこれら3軸の **産業化** が現実化している。`Cochise`(Reference Harness)、`ExploitBench`(能力ラダー)、`MemRepair`(階層メモリ修復) など、**標準化と実用化の両方**が同時に進む。残課題は、攻防両側のエージェントが**実世界で接触した時の挙動**（攻撃側の自律進化が防御側の対応速度を超える可能性）。

### 4.2 攻撃側エージェントの標準化

#### [May 2026] "Cochise: A Reference Harness for Autonomous Penetration Testing" [[paper](https://arxiv.org/abs/2605.11671)]

- **概要（推定）**: 自律的ペネトレーションテストのための**参照ハーネス実装**。MetasploitやBurp Suite等の既存ツールを統合し、LLMエージェントがペンテストワークフローを実行するための標準的な実行環境を提供する。
- **差分・新規性（推定）**: 4月号で扱った AutoPT 系論文が「**手法**」を提案していたのに対し、本論文は**参照実装そのもの**を提供する点が産業化の重要な一歩。これは Cybersecurity 版の `OpenHands`(2407.16741) とも言える位置づけ。今後の攻撃側研究の事実上のベースラインになる可能性。

#### [May 2026] "Pen-Strategist: A Reasoning Framework for Penetration Testing Strategy Formation and Analysis" [[paper](https://arxiv.org/abs/2605.04499)]

- **概要（推定）**: ペンテストの**戦略形成**段階に推論フレームワークを導入。具体的なエクスプロイト実行ではなく、攻撃計画の立案・優先順位付け・リソース割当を扱う。
- **差分・新規性（推定）**: 既存のペンテストエージェントは「ツール呼び出し」レベルの実装が中心だったが、本研究は**戦略レベル**を主題化する。`From Plan to Action`(2604.12147) で扱われた計画追従性の問題を、サイバー攻撃ドメインに特化させた形。

#### [May 2026] "From Controlled to the Wild: Evaluation of Pentesting Agents for the Real-World" [[paper](https://arxiv.org/abs/2605.10834)]

- **概要（推定）**: 制御環境（CTF、HackTheBox等）で訓練されたペンテストエージェントを**実世界システム**で評価した実証研究。
- **差分・新規性（推定）**: 4月号の `DefenderBench` や 200チャレンジCTF統一評価が**制御環境内の能力評価**だったのに対し、本研究は**transfer gap**（制御→実世界の性能差）を明示的に測定する。`WildClawBench`([paper](https://arxiv.org/abs/2605.10912)) と思想を共有する「**Wild benchmark**」潮流の一部。

#### [May 2026] "Autonomous LLM Agents & CTFs: A Second Look" [[paper](https://arxiv.org/abs/2605.21497)]

- **概要（推定）**: 1年前の自律エージェント+CTF評価を**再検証**する研究。タイトルの「Second Look」から、過去の評価結果の再現性・現代のモデル能力での検証 を主題化していると推定される。
- **差分・新規性（推定）**: 再現性研究は珍しいが重要。AIエージェント研究全体で**ベンチマーク汚染**や**評価条件の差異**が問題化している中、サイバーセキュリティドメインで明示的に再検証する点が意義深い。

### 4.3 ベンチマーク・能力ラダー

#### [May 2026] "ExploitBench: A Capability Ladder Benchmark for LLM Cybersecurity Agents" [[paper](https://arxiv.org/abs/2605.14153)] ⚖️

- **概要（推定）**: サイバーセキュリティエージェントの能力を**ラダー（梯子）形式**で測定するベンチマーク。タスクを難易度順に並べ、エージェントが「どこまで登れるか」を明示する。
- **差分・新規性（推定）**: 4月号の `DefenderBench` が4領域横断の能力評価だったのに対し、本ベンチは **垂直方向の難易度勾配**を主軸にする。これは AGI 系評価（GAIAやMMAUなど）で見られたラダー形式の発想を、サイバーセキュリティに適用したもの。**「現在のフロンティアモデルが攻撃能力でどこまで来ているか」** を一次元で可視化する効果が大きい。今後、規制議論で頻繁に引用される可能性。

#### [May 2026] "CyBiasBench: Benchmarking Bias in LLM Agents for Cyber-Attack Scenarios" [[paper](https://arxiv.org/abs/2605.07830)] ⚖️

- **概要（推定）**: サイバー攻撃シナリオでLLMエージェントが**特定の攻撃手法・対象に偏る**バイアスを測定するベンチマーク。
- **差分・新規性（推定）**: 攻撃能力そのものではなく**攻撃の偏り**を測る点が新しい。これは防御側にとって重要な情報で、「**エージェント攻撃者がどこを狙いがちか**」を知ることで防御の優先順位を決められる。

### 4.4 防御側エージェント

#### [May 2026] "MemRepair: Hierarchical Memory for Agentic Repository-Level Vulnerability Repair" [[paper](https://arxiv.org/abs/2605.17444)]

- **概要（推定）**: リポジトリレベルの脆弱性修復に**階層メモリ**を導入。コードベース全体の構造・依存関係・過去の修復履歴を階層化したメモリで保持し、修復精度を向上。
- **差分・新規性（推定）**: 既存の脆弱性修復は個別関数レベルの修正が中心だったが、本研究は **リポジトリ全体のコンテキスト** を一級市民として扱う。Software Agents セクションの `Root-Cause-Driven Automated Vulnerability Repair`([paper](https://arxiv.org/abs/2605.04251)) と組み合わせると、「**根本原因をリポジトリ階層メモリで特定し、修復する**」一貫した方法論が形成される。

#### [May 2026] "Root-Cause-Driven Automated Vulnerability Repair" [[paper](https://arxiv.org/abs/2605.04251)]

- **概要（推定）**: 脆弱性修復を**症状ではなく根本原因（root cause）** から行うアプローチ。表面的なパッチではなく、設計レベルの欠陥に遡って修正。
- **差分・新規性（推定）**: 既存の APR (Automated Program Repair) はテストケースを通すパッチ生成が中心だったが、本研究は **「なぜこのバグが発生したか」** の因果分析を起点とする。MemRepair と相補的で、組み合わせることで実用的な防御パイプラインを構成可能。

#### [May 2026] "Generating Proof-of-Vulnerability Tests to Help Enhance the Security of Complex Software" [[paper](https://arxiv.org/abs/2605.03956)]

- **概要（推定）**: 脆弱性の**証明テスト（PoV: Proof of Vulnerability）** を自動生成する手法。脆弱性報告だけでなく、その存在を再現可能な形で実証するテストを提供。
- **差分・新規性（推定）**: 既存の SAST/DAST が脆弱性の指摘止まりだったのに対し、本研究は**再現可能な証明**まで提供する。これは防御側のトリアージ効率を大幅に上げる実用的な貢献。

### 4.5 産業化と警告

#### [May 2026] "Agentic AI and the Industrialization of Cyber Offense: Forecast, Consequences, and Defensive Priorities for Enterprises and the Mittelstand" [[paper](https://arxiv.org/abs/2605.06713)]

- **概要（推定）**: エージェント型AIによるサイバー攻撃の**産業化**を予測し、特に**中堅企業（Mittelstand）** への影響を分析するポリシー寄りの論文。
- **差分・新規性（推定）**: 学術的攻撃手法研究ではなく、**産業界・特に中堅企業向けの戦略提言**という珍しい論調。4月号で予測した「攻撃の産業化」が現実化する中で、防御側の準備状況の格差（大企業 vs 中堅）を主題化する。今後の AI 規制議論で参照される可能性が高い。

### 4.6 NOT_FOUND論文（タイトルのみ）

以下の論文はarxiv IDが確認できなかったが、タイトルから内容を推定する:

- **"GenAI-Driven Threat Detection with Microsoft Security Copilot"**: 商用エージェント（MS Copilot）の実運用知見を共有する産業論文と推定。
- **"When Skills Don't Help: A Negative Result on Procedural Knowledge for Tool-Grounded Agents in Offensive Cybersecurity"**: スキル/手続き知識が攻撃に必ずしも有用ではないという**負の結果**を報告。スキル研究全般の楽観論への重要な反証となる可能性。
- **"Three Heads Are Better Than One: A Multi-perspective Reasoning Framework for Enhanced Vulnerability Detection"**: 複数視点の推論を脆弱性検知に適用。Multi-Agent の文脈とも近い。
- **"AgentModernize: Preserving Business Logic in Legacy Modernization with Multi-Agent LLMs and Behavioral Specification Graphs"**: レガシーシステムの近代化を、業務ロジックを保存しつつマルチエージェントで実施。Enterprise セクションの `Reversa`([paper](https://arxiv.org/abs/2605.18684)) と類似テーマ。

### 4.7 横断的示唆

サイバーセキュリティ分野は **「研究 → 産業化」のフェーズ移行が最も速い**領域になっている。実装者向けTipsとして:

1. **`Cochise` のような Reference Harness を採用**: 自作するより既存実装をベースに。
2. **`ExploitBench` の能力ラダーで自社モデルを評価**: 規制議論への準備にもなる。
3. **`MemRepair` の階層メモリは脆弱性修復だけでなく、リポジトリ全体の理解にも応用可能**。
4. **`Generating Proof-of-Vulnerability Tests` の再現テスト生成**は CI/CD への組み込みが効果的。
5. **「攻撃の産業化」への対策**: 中堅企業は特に、SOC運用へのエージェント導入を計画的に進める必要。

## 5. Software Agents: 「生成」から「ライフサイクル」へ

### 5.1 このジャンルのトレンドと課題感

🔍 2024〜2025年の Software Agents 研究は **「コード生成」競争**（SWE-bench 系の SOTA レース）が主軸だった。今期は明確に**「コードのライフサイクル全体」**（生成→レビュー→保守→修復）への関心移行が起きている。背景には、**エージェント生成コードの実運用での問題**（保守性、レビュー困難、隠れたバグ）が現実問題化していることがある。残課題は、エージェント生成コードに特化した**品質指標**の確立。

### 5.2 エージェント生成コードの保守問題

#### [May 2026] "To What Extent Does Agent-generated Code Require Maintenance? An Empirical Study" [[paper](https://arxiv.org/abs/2605.06464)]

- **概要（推定）**: エージェント生成コードが運用に入った後、**どの程度の保守工数を必要とするか** を実証研究。タイトルから、複数プロジェクト・複数エージェントを対象にした empirical study と推定される。
- **差分・新規性（推定）**: 既存研究は「**生成時点の品質**」（テスト通過率、コードスタイル等）が中心だったが、本研究は**運用後の保守コスト**という見落とされがちな指標を測定する。`Beyond Bug Fixes`(2601.20109) や `How do Agents Refactor`(2601.20160) と並ぶ、「**エージェント生成コードの社会的影響**」を扱う empirical research の流れ。

#### [May 2026] "Rethinking Code Review in the Age of AI: A Vision for Agentic Code Review"

- **概要（推定）**: コードレビュー自体をエージェント化するビジョンペーパー。タイトルから、レビュアーエージェントの役割・人間レビュアーとの分業・レビュー品質の評価軸 を主題化していると推定。
- **差分・新規性（推定）**: 3月の `CR-Bench`(2603.11078) がレビューエージェントの**評価**を扱ったのに対し、本研究はレビューの**プロセスとロール定義** を再設計する規範的論文。Agentic Workflow の中でレビューを一級市民化する流れ。

### 5.3 セキュリティ修復への深化

#### [May 2026] "Root-Cause-Driven Automated Vulnerability Repair" [[paper](https://arxiv.org/abs/2605.04251)]

Cybersecurity セクションで詳述。Software Agents 文脈では、**自動プログラム修復（APR）の方向転換**として位置づく。テスト通過ベースのパッチから、設計レベルの修正へ。

#### [May 2026] "MemRepair: Hierarchical Memory for Agentic Repository-Level Vulnerability Repair" [[paper](https://arxiv.org/abs/2605.17444)]

Cybersecurity セクションで詳述。Software Agents 文脈では、**リポジトリレベルの文脈理解**を実現する手法として、`Improving Code Localization with Repository Memory`(2510.01003) の発展形と見ることができる。

### 5.4 データ合成とベンチマーク

#### [May 2026] "FrontierSmith: Synthesizing Open-Ended Coding Problems at Scale" [[paper](https://arxiv.org/abs/2605.14445)]

- **概要（推定）**: コーディング問題を大規模に**オープンエンドに合成**するパイプライン。SWE-bench 系の限界（タスクが固定、ベンチ汚染リスク）を超えるため、難易度・領域を制御しながら問題を生成。
- **差分・新規性（推定）**: 既存のコーディング問題合成（HumanEval や MBPP の拡張）は閉じた形式が中心だったが、本研究は **オープンエンド** を主題化する。Cybersecurity セクションの `Generating Proof-of-Vulnerability Tests`([paper](https://arxiv.org/abs/2605.03956)) と同様、**合成データのスケーリング**競争の一部。リスクとしては、合成データが将来のベンチマークを汚染する可能性。

### 5.5 横断的示唆

Software Agents の今期トレンドは、**「コードを書く能力」から「コードと共に生きる能力」** への重心移動。実装者向けTipsとして:

1. **エージェント生成コードの保守性を独立評価**: 単に動くだけでなく、6ヶ月後の修正容易性を測る。
2. **コードレビューエージェントを CI に組み込む**: ただし、人間レビュアーとの役割分担を明確に。
3. **脆弱性修復は根本原因から**: `Root-Cause-Driven` の発想を CI/CD パイプラインに組み込む。
4. **リポジトリ全体の階層メモリ**: `MemRepair` の発想は脆弱性修復以外（リファクタリング、ドキュメント生成）にも応用可能。

## 6. Deep Research / Retrieval: 長期化と自己進化

### 6.1 このジャンルのトレンドと課題感

🔍 Deep Research 系の研究は3〜4月にかけて**ベンチマークラッシュ**（RESEARCHRUBRICS, DeepResearch Bench II 等）を経験し、評価基盤が整った。5月は「次の能力境界」を探る研究が中心。特に **(1) 長期検索のコンテキスト管理**、**(2) エンタープライズ知識への適応**、**(3) 検索戦略自体の自己進化** の3軸が顕在化。残課題は、**並列検索結果の統合**（信頼性とスケーラビリティの両立）。

### 6.2 長期検索のコンテキスト管理

#### [May 2026] "LongSeeker: Elastic Context Orchestration for Long-Horizon Search Agents" [[paper](https://arxiv.org/abs/2605.05191)]

- **概要（推定）**: 長期検索エージェント向けに**コンテキストを弾性的（elastic）にオーケストレーション**する手法。検索の進行に応じて、コンテキストウィンドウの中身を動的に拡縮・入れ替えする。
- **差分・新規性（推定）**: 既存の long-context 手法は **静的な圧縮**（要約、トリミング）が中心だったが、本研究は**タスクの進行状態に応じた動的管理**を提案。Reasoning セクションでも引用される横断的論文で、**Long-Horizon タスクの基本要素技術**として位置づく可能性。

#### [May 2026] "Scaling Retrieval-Augmented Reasoning with Parallel Search and Explicit Merging"

- **概要（推定）**: 並列検索の結果を**明示的にマージ**することで RAG の推論能力をスケールする。タイトルから、マージ過程を透明化することで結果の説明可能性も向上させる設計と推定。
- **差分・新規性（推定）**: 既存の並列 RAG は結果を暗黙的に集約していたが、本研究は**マージ過程の明示化**を主題化。Multi-Agent セクションの `Recursive Agent Optimization`([paper](https://arxiv.org/abs/2605.06639)) と同様、**再帰的並列化**の流れの一部。

### 6.3 エンタープライズ知識への適応

#### [May 2026] "AgenticRAG: Agentic Retrieval for Enterprise Knowledge Bases" [[paper](https://arxiv.org/abs/2605.05538)]

- **概要（推定）**: 企業ナレッジベース向けの Agentic RAG。一般的な web RAG とは異なる、**アクセス制御・データガバナンス・部門間横断**を考慮した設計。
- **差分・新規性（推定）**: 既存の Agentic RAG（2501.09136 サーベイ等）が技術中心だったのに対し、本研究は**エンタープライズ運用要件**を一級市民化。`Beyond Text-to-SQL`([paper](https://arxiv.org/abs/2605.21027)) と並んで、エンタープライズ採用フェーズの実用研究。

### 6.4 検索の超知能化

#### [May 2026] "Superintelligent Retrieval Agent: The Next Frontier of Information Retrieval" [[paper](https://arxiv.org/abs/2605.06647)] 🔥

- **概要（推定）**: 情報検索の次世代を「超知能（superintelligent）検索エージェント」として位置づけるビジョンペーパー。タイトルから、現状の RAG/Deep Research を超えた、**人間検索者を凌駕するエージェント**像を提示すると推定。
- **差分・新規性（推定）**: 6月の `Build the web for agents, not agents for the web`(2506.10953) の延長線上にある、検索エコシステム全体の再設計提案。今後数年の IR 研究の方向性を示すフラッグシップ論文になる可能性。Meta 等の大手研究機関からのビジョンペーパーと推定。

### 6.5 検索の自己進化

#### [May 2026] "Towards Self-Evolving Agentic Literature Retrieval" [[paper](https://arxiv.org/abs/2605.14306)]

- **概要（推定）**: 文献検索エージェントが**過去のクエリ・結果から検索戦略を進化**させる。
- **差分・新規性（推定）**: 既存の Deep Research は静的な検索戦略だったが、本研究は **ユーザ固有・分野固有の検索パターンを学習**する。Self-Evolution セクションでも触れたが、Deep Research の文脈では「**個別ユーザへのパーソナライズ**」の重要な一歩。`NanoResearch`([paper](https://arxiv.org/abs/2605.10813)) と組み合わせると、研究者個人の長期パートナーとなる Deep Research エージェントの設計が見える。

### 6.6 横断的示唆

Deep Research の今期トレンドは **「汎用検索能力」から「タスク・ユーザ特化の進化型検索」** へ。実装者向けTipsとして:

1. **コンテキスト管理を弾性的に**: `LongSeeker` の発想で、タスクフェーズに応じてコンテキスト中身を変える。
2. **並列検索結果のマージを明示**: 透明性とスケーラビリティの両立。
3. **エンタープライズ要件を分離設計**: `AgenticRAG` のように、ガバナンス層を検索層と分けて実装。
4. **検索戦略の進化を組み込む**: `Towards Self-Evolving Agentic Literature Retrieval` の発想を、検索ログから学ぶ仕組みとして実装。

## 7. Multi-Agent / Orchestration: ベイズ整合性と失敗帰属

### 7.1 このジャンルのトレンドと課題感

🔍 Multi-Agent 研究は2024〜2025年にかけて **(a) フレームワーク**（AutoGen, MetaGPT等）、**(b) オーケストレーション最適化**（AgentNet等）、**(c) 評価**（BOLAA等）の3段階を経た。今期は **理論的基盤**（ベイズ整合性）と **運用問題**（失敗帰属、状態管理）が主題化されている。残課題は、マルチエージェント系の **形式的検証可能性**（個別エージェントの正しさから系全体の正しさを導けるか）。

### 7.2 理論的基盤の提案

#### [May 2026] "Position: agentic AI orchestration should be Bayes-consistent" [[paper](https://arxiv.org/abs/2605.00742)] 🔥

- **概要（推定）**: エージェントAIのオーケストレーションは**ベイズ的整合性（Bayes-consistency）** を満たすべきだという規範的ポジションペーパー。複数エージェントの確率的推論が系全体で矛盾しない条件を理論的に整理。
- **差分・新規性（推定）**: 既存の Multi-Agent 研究は経験的・工学的アプローチが主流だったが、本研究は**統計理論からの規範**を提示する。`Towards a Science of Collective AI`(2602.05289) で提唱された「collective AI の科学」への具体的応答。今後、マルチエージェント系の正しさを論じる際の**理論的座標軸**として頻繁に参照される可能性。

### 7.3 再帰的最適化

#### [May 2026] "Recursive Agent Optimization" [[paper](https://arxiv.org/abs/2605.06639)] 🔥

- **概要（推定）**: エージェントを最適化するエージェント自体を再帰的に最適化する。`Recursive Multi-Agent Systems`(2604.25917) の延長線上にあると推定。
- **差分・新規性（推定）**: 既存の自己最適化研究（ASI-Evolve 等）は基本的に**フラットな最適化ループ**だったが、本研究は**最適化階層自体を最適化対象に含める**点が新しい。理論的にはメタ強化学習やバイレベル最適化との接続があるが、エージェントAIの文脈で正面から扱った点が貢献。Self-Evolution の `Ratchet`([paper](https://arxiv.org/abs/2605.22148)) で導入された衛生レシピと組み合わせる必要がある。

### 7.4 失敗帰属の体系化

#### [May 2026] "Beyond Individual Intelligence: Surveying Collaboration, Failure Attribution, and Self-Evolution in LLM-based Multi-Agent Systems" [[paper](https://arxiv.org/abs/2605.14892)] 📖

- **概要（推定）**: マルチエージェント系の **協調・失敗帰属・自己進化** を主軸にしたサーベイ。タイトルから、特に **「複数エージェントが関わる失敗の原因特定」** を中心テーマにすると推定。
- **差分・新規性（推定）**: マルチエージェントサーベイは多いが、**失敗帰属（failure attribution）** を主題化したサーベイは初。これは `AGENTRX`(2602.02475) や `AgenTracer`(2509.03312) で個別研究は出ていたものの、サーベイレベルでの体系化はなかった。実装者にとって、**マルチエージェント系の運用問題の地図**として価値が高い。

### 7.5 状態管理の明示化

#### [May 2026] "Multi-agent Collaboration with State Management" [[paper](https://arxiv.org/abs/2605.20563)]

- **概要（推定）**: マルチエージェント協調における**状態管理**を明示的に設計する。既存のマルチエージェント系が状態を暗黙的に保持していたのに対し、共有状態・個別状態の境界を明確化。
- **差分・新規性（推定）**: ソフトウェア工学のステートマシン的発想をマルチエージェントに持ち込む。`MetaAgent: Automatically Constructing Multi-Agent Systems Based on Finite State Machines`(2507.22606) の発展形と見ることができる。

### 7.6 横断的示唆

Multi-Agent の今期トレンドは **「協調パターンの発明」から「協調の理論的・運用的基盤整備」** へ。実装者向けTipsとして:

1. **エージェント間の確率推論を整合性チェック**: `Bayes-consistent orchestration` の発想を、エージェント間のメッセージ交換でルーチン化。
2. **失敗帰属用のトレースID**を全メッセージに伝播: 後から原因を辿れる構造に。
3. **状態管理を明示的に**: 暗黙的な共有状態は技術的負債になる。
4. **再帰的最適化は強力だが、Hygiene が必須**: `Ratchet` 系の衛生レシピと組み合わせる。

## 8. Safety & Governance: 行動評価批判と監視可能性

### 8.1 このジャンルのトレンドと課題感

🔍 Safety 研究は2025年後半から **(a) 攻撃面の体系化**、**(b) 防御レイヤの分化**、**(c) ベンチマーク化** の3軸で成熟した（4月号サイバーセキュリティニュースレター参照）。5月は **規範論**（何を安全と呼ぶか）が中心になっている。特に `Position: Behavioural Assurance Cannot Verify the Safety Claims Governance Now Demands` は、現行の評価パラダイム自体への根源的疑義を提起する重要論文。残課題は、行動評価を超える**形式的・構造的安全保証**の確立。

### 8.2 行動評価パラダイムへの批判

#### [May 2026] "Position: Behavioural Assurance Cannot Verify the Safety Claims Governance Now Demands" [[paper](https://arxiv.org/abs/2605.15164)] 🔥

- **概要（推定）**: AIガバナンスが要求する安全保証（safety claims）は、**行動評価（behavioural assurance）だけでは原理的に検証不能**だと論じるポジションペーパー。タイトルから、行動評価の限界を整理し、ホワイトボックス監査・形式手法・構造的検証の必要性を提起すると推定。
- **差分・新規性（推定）**: 現在の AI 安全評価のほぼ全てが入出力ベースの行動評価（red-teaming, benchmarks）に依拠しているが、本論文は**そのパラダイム全体を疑う**。これは AI 規制議論（EU AI Act, US Executive Order）の前提を揺るがす可能性のある重要論文。今後の安全研究の方向性を変える可能性が高い。Skills セクションの `SkillScope`([paper](https://arxiv.org/abs/2605.05868)) や `Auditing Agent Harness Safety`([paper](https://arxiv.org/abs/2605.14271)) の構造的監査の流れと呼応する。

### 8.3 可観測性の基盤再評価

#### [Jan 2024] "Visibility into AI Agents" [[paper](https://arxiv.org/abs/2401.13138)] 🔥

- **概要**: 2024年1月公開の FAccT '24 論文だが、今期のガバナンス議論で再注目されてリストに追加。エージェント運用の **可観測性（visibility）** を、エージェントID・実行ログ・ユーザ通知の3層で整理する基礎論文。
- **差分・新規性**: 2年経った今でも参照される基礎論文。`Position: Behavioural Assurance...` の議論を補完する「**何を観測すべきか**」の規範枠組みとして機能する。

### 8.4 メモリ層での安全強化

#### [May 2026] "SafeHarbor: Defining Precise Decision Boundaries via Hierarchical Memory-Augmented Guardrail for LLM Agent Safety" [[paper](https://arxiv.org/abs/2605.05704)]

- **概要（推定）**: 階層メモリで補強されたガードレールにより、エージェントの**決定境界（decision boundaries）** を厳密に定義する安全機構。
- **差分・新規性（推定）**: 既存のガードレール（入出力フィルタ）が**点的な制約**だったのに対し、本研究は**メモリ階層を用いた構造的境界**を提案。`SSGM`(2603.11768) のメモリガバナンスを安全側に発展させたものと見ることができる。

### 8.5 ツール出力の不信前提

#### [May 2026] "Trust No Tool: Evaluating and Defending LLM Agents under Untrusted Tool Feedback" [[paper](https://arxiv.org/abs/2605.17453)]

- **概要（推定）**: ツール出力が信頼できない前提（**Trust No Tool**）でエージェントを評価・防御する。タイトルから、ツール出力への盲信が攻撃ベクタになることを示し、検証ラッパーを提案すると推定。
- **差分・新規性（推定）**: 既存のエージェントはツール出力を所与のものとして扱うことが多かったが、本研究は **「ツール出力 = 信頼できない外部入力」** という前提を持ち込む。`SkillScope`([paper](https://arxiv.org/abs/2605.05868)) の最小権限と組み合わせると、**信頼性が階層化されたエージェントアーキテクチャ**が見える。

### 8.6 NOT_FOUND論文

- **"Proteus: A Self-Evolving Red Team for Agent Skill Ecosystems"**: Skills セクションで詳述。スキル進化と同期する攻撃エージェント。
- **"MonitoringBench: Semi-Automated Red-Teaming for Agent Monitoring"**: モニタリング機構自体へのレッドチームを半自動化するベンチマーク。`Visibility into AI Agents` の運用品質を測る試みと推定される。

### 8.7 横断的示唆

Safety の今期トレンドは **「行動評価への依存からの脱却」**。実装者向けTipsとして:

1. **行動評価だけに依存しない**: `Position: Behavioural Assurance...` の警告を真剣に受け止め、構造的監査を併用。
2. **ハーネスレベルの監査**を独立した layer として実装（`Auditing Agent Harness Safety`）。
3. **ツール出力を信頼しない**設計: `Trust No Tool` の発想を入出力境界に適用。
4. **可観測性は事後ではなく事前設計**: `Visibility into AI Agents` の3層（ID/ログ/通知）を最初から組み込む。
5. **メモリ・スキル・ハーネス各層で安全を構造化**: 単一のガードレールに頼らない多層防御。

## 9. Evaluation: 実環境ベンチと相互作用評価

### 9.1 このジャンルのトレンドと課題感

🔍 Evaluation 研究は2025年に **`Holistic Agent Leaderboard`**(2510.11977) や **`Automating Benchmark Design`**(2510.25039) で大きく前進した。今期は **(1) 実世界転移**（Wild benchmark）、**(2) 評価そのものの設計科学化**、**(3) 多階層評価**の3軸が顕在化。残課題は、**ベンチマーク汚染と継続的更新の両立**。

### 9.2 実世界転移ベンチ

#### [May 2026] "WildClawBench: A Benchmark for Real-World, Long-Horizon Agent Evaluation" [[paper](https://arxiv.org/abs/2605.10912)] ⚖️

- **概要（推定）**: 実世界の長期タスクを対象としたベンチマーク。"Wild" という命名から、制御環境ではなく**実際のサービス・API・組織コンテキスト**を含む評価設定と推定。
- **差分・新規性（推定）**: 4月の `LiveClawBench`(2604.13072) や `OS-Marathon`(2601.20650) の流れを継ぎ、**長期 × 実世界**という最も困難な評価設定に挑む。Cybersecurity の `From Controlled to the Wild`([paper](https://arxiv.org/abs/2605.10834)) と思想を共有する「**Wild benchmark**」潮流の代表例。

#### [Apr 2026] "ClawGym: A Scalable Framework for Building Effective Claw Agents" [[paper](https://arxiv.org/abs/2604.26904)]

- **概要（推定）**: Claw 系エージェントの構築フレームワーク。OpenAI Gym 的なインターフェースで、エージェントの訓練・評価を統一する。
- **差分・新規性（推定）**: `MEMGYM`([paper](https://arxiv.org/abs/2605.20833)) と同様、**訓練と評価を統一する環境**の整備。

### 9.3 評価の自動化

#### [May 2026] "Agentic CLEAR: Automating Multi-Level Evaluation of LLM Agents" [[paper](https://arxiv.org/abs/2605.22608)]

- **概要（推定）**: 7月の `CLEAR: Error Analysis via LLM-as-a-Judge Made Easy`(2507.18392) のエージェント版・多階層版。エージェントの評価を複数の階層（タスク全体・サブタスク・個別アクション）で自動化。
- **差分・新規性（推定）**: 既存の LLM-as-a-Judge は単一階層が中心だったが、本研究は **階層構造化された評価** を扱う。マルチエージェント系の failure attribution（`Beyond Individual Intelligence`([paper](https://arxiv.org/abs/2605.14892))）と組み合わせると、**階層的かつ因果的な失敗分析**が可能になる。

### 9.4 評価の設計科学

#### [May 2026] "Interactive Evaluation Requires a Design Science"

- **概要（推定）**: インタラクティブな評価（人間と AI の相互作用を含む評価）には**設計科学（design science）的アプローチ**が必要だと論じるポジションペーパー。
- **差分・新規性（推定）**: 評価メトリクスや手法ではなく、**評価設計のメタプロセス**を主題化する珍しい論文。`Holistic Agent Leaderboard`(2510.11977) で示された「評価インフラの欠如」への規範的応答とも読める。HCI 系研究との接続が想定される。

### 9.5 横断的示唆

Evaluation の今期トレンドは **「静的ベンチから動的・相互作用的評価」** へ。実装者向けTipsとして:

1. **Live benchmark を必ず併用**: 静的ベンチは汚染リスクが高い。
2. **多階層評価を自動化**: `Agentic CLEAR` の発想で、タスク・サブタスク・アクション各層で評価。
3. **インタラクティブ評価の設計を意識**: 単発の正解判定ではなく、対話・修正の流れも評価対象。
4. **失敗の階層的分析**を組み込む: 単純な成功率ではなく、どの階層で失敗したかを記録。

## 10. Harness & Environment: モデル外の "OS層" 研究

### 10.1 このジャンルのトレンドと課題感

🔍 Environment 研究は当初**世界モデル・シミュレーション**が主軸だったが、3月の `AutoHarness`(2603.03329)・`Natural-Language Agent Harnesses`(2603.25723) を経て、**「Agent Harness」** という独立した研究対象が確立した。今期は、ハーネス自体の**設計学・監査・適応**が同時並行で立ち上がっている。残課題は、ハーネス標準化（**OCI Registry的なもの**）と、ハーネス進化の安全性。

### 10.2 ハーネスをコードとして扱う

#### [May 2026] "Code as Agent Harness" [[paper](https://arxiv.org/abs/2605.18747)]

- **概要**: 42名の著者（Xuying Ning 等）によるハーネス研究。タイトルから、**ハーネスをコードとして扱う**（バージョン管理・テスト可能・再利用可能）パラダイムを提案。
- **差分・新規性（推定）**: 既存のハーネスは**設定ファイル + ad-hoc スクリプト**で構成されることが多かったが、本研究は **「ハーネス = ファーストクラスのコード」** として扱う規範を打ち立てる。これは Skills の `SkillGenBench`([paper](https://arxiv.org/abs/2605.18693)) と並んで、**エージェント周辺の工学化**を推進する重要論文。

### 10.3 インターフェース適応の発見

#### [May 2026] "Adapting the Interface, Not the Model: Runtime Harness Adaptation for Deterministic LLM Agents" [[paper](https://arxiv.org/abs/2605.22166)]

- **概要（推定）**: 性能改善のためにモデルではなく**インターフェース側を適応**させる。タイトルから、ランタイムでハーネスを動的に調整することで、エージェントの**決定論性（determinism）** を高めると推定。
- **差分・新規性（推定）**: これは極めて重要な視点転換。「**多くの性能問題はモデルではなくハーネス設計に起因する**」という主張を実証する論文。`Is Grep All You Need?`([paper](https://arxiv.org/abs/2605.15184)) と思想を共有し、**過剰な抽象化を避ける**ミニマリズム潮流の一部。

#### [May 2026] "Is Grep All You Need? How Agent Harnesses Reshape Agentic Search" [[paper](https://arxiv.org/abs/2605.15184)] 🔥

- **概要（推定）**: 単純なツール（`grep`）が、適切なハーネス設計を通じて**強力な検索装置**になることを実証。タイトルから、複雑な RAG パイプラインに頼らず、Unix tools + 適切なハーネスで匹敵する性能を出せることを示すと推定。
- **差分・新規性（推定）**: 既存の Agentic Search は複雑な RAG パイプライン（埋め込み + ベクタDB + リランク）が主流だったが、本研究は **「シンプルさへの回帰」** を提案。`Code as Agent Harness`([paper](https://arxiv.org/abs/2605.18747)) と組み合わせると、「**コードベースのシンプルなハーネス**」が次のパラダイムになる可能性。

### 10.4 ハーネス安全性の監査

#### [May 2026] "Auditing Agent Harness Safety" [[paper](https://arxiv.org/abs/2605.14271)] ⚖️

- **概要（推定）**: ハーネス自体の安全性を**監査**するベンチマーク・手法。エージェントの行動ではなく、**ハーネスの設計が安全特性に与える影響**を測定。
- **差分・新規性（推定）**: 既存の安全評価はモデルやプロンプト中心だったが、本研究は **「ハーネスも安全性の重要構成要素」** という認識を提示。`Position: Behavioural Assurance...`([paper](https://arxiv.org/abs/2605.15164)) の構造的監査の流れを、ハーネスレベルで具現化したもの。

### 10.5 進化と Priors

#### [May 2026] "Harnessing Agentic Evolution" [[paper](https://arxiv.org/abs/2605.13821)]

- **概要（推定）**: エージェント進化を**ハーネス側からコントロール**するアプローチ。エージェント内部ではなく、ハーネスが進化の方向性を制約・誘導。
- **差分・新規性（推定）**: 既存の自己進化研究はエージェント内部の機構が中心だったが、本研究は**外部からの進化制御**を提案。Self-Evolution の `Ratchet`([paper](https://arxiv.org/abs/2605.22148)) と組み合わせると、**ハーネスレベルでの衛生強制**が実現可能。

#### [May 2026] "PriorZero: Bridging Language Priors and World Models for Decision Making" [[paper](https://arxiv.org/abs/2605.12289)]

- **概要（推定）**: LLM の言語事前知識（language priors）と世界モデルを橋渡しする手法。意思決定タスクでの両者の統合を扱う。
- **差分・新規性（推定）**: 世界モデル研究と LLM エージェント研究はやや分断していたが、本研究は両者を**事前知識の補完関係**として統合する。Environment セクション全体の**世界モデル vs ハーネス**の対立を解消する方向性。

### 10.6 NOT_FOUND論文

- **"Interactive Evaluation Requires a Design Science"**: Evaluation セクションで詳述。ハーネス文脈では、ハーネス設計自体が設計科学的アプローチを必要とする示唆。
- **"HarnessAPI: A Skill-First Framework for Unified Streaming APIs and MCP Tools"**: スキルファーストでストリーミング API と MCP ツールを統合するフレームワーク。MCP 標準化との接続を意図したものと推定。

### 10.7 横断的示唆

Harness の今期トレンドは **「モデルを賢く」から「モデルの周辺を賢く」** への重心移動。実装者向けTipsとして:

1. **モデル変更の前にハーネス見直し**: `Adapting the Interface, Not the Model` の警告を実践。
2. **既存のシンプルなツールを再評価**: `grep`、Unix tools、シンプルな関数呼び出しが、適切なハーネスで強力。`Is Grep All You Need?` の示唆。
3. **ハーネスをコードとして管理**: バージョン管理、テスト、レビューの対象に。
4. **ハーネス安全性も独立に監査**: `Auditing Agent Harness Safety` の発想。
5. **進化をハーネス側から制御**: `Harnessing Agentic Evolution` の発想で、内部進化と外部統制を分離。

## 11. Research Agents: 「AI Scientist」への懐疑

### 11.1 このジャンルのトレンドと課題感

🔍 Research Agents（科学エージェント）分野は2024年の `The AI Scientist`(2408.06292) 以来、急速に拡大した。`AI Scientist-v2`(2504.08066)・`AlphaResearch`(2511.08522) など、自律性の高さを競う論文が次々に出現した。今期は**懐疑的論調**が顕在化し、「**完全自動の科学者**」幻想からの脱却が進んでいる。残課題は、**「自動化と人間レビューの最適配分」** の確立。

### 11.2 科学エージェント懐疑論

#### [May 2026] "Agentic AI Scientists Are Not Built For Autonomous Scientific Discovery" [[paper](https://arxiv.org/abs/2605.08956)] 🔥

- **概要（推定）**: 現状の Agentic AI Scientists は**自律的科学発見には設計されていない**と論じる批判的論文。タイトルから、AI Scientist 系研究の根本的限界を整理すると推定。
- **差分・新規性（推定）**: `AI Scientists Fail Without Strong Implementation Capability`(2506.01372)、`Why LLMs Aren't Scientists Yet`(2601.03315)、`AI scientists produce results without reasoning scientifically`(2604.18805) の流れを汲む、**懐疑論の決定版**となる可能性。これらの批判的論文の累積が、今後の研究エージェント設計の方向性を変える可能性が高い。

### 11.3 AIレビュアーの実証評価

#### [May 2026] "On the limits and opportunities of AI reviewers: Reviewing the reviews of Nature-family papers with 45 expert scientists" [[paper](https://arxiv.org/abs/2605.20668)] 🔥

- **概要**: 著者 Seungone Kim, Dongkeun Yoon, Kiril Gashteovski 等60名による大規模実証研究。**45名の専門科学者**が AI レビューと人間レビューを比較評価。Nature 系論文を対象とした厳密な研究。
- **差分・新規性**: 既存の AI レビュアー研究（`LLM-REVal`(2510.12367)、`AI and the Future of Academic Peer Review`(2509.14189)）が小規模・限定的だったのに対し、本研究は**Nature 系・45名・分野横断**という規模で、AIレビュアーの**実用限界**を厳密に測定。今後の peer review 議論の基本文献となる。

#### [Apr 2026] "Can AI Be a Good Peer Reviewer? A Survey of Peer Review Process, Evaluation, and the Future" [[paper](https://arxiv.org/abs/2604.27924)] 📖

- **概要（推定）**: AI ピアレビューの**プロセス・評価・将来**を整理するサーベイ。`On the limits and opportunities of AI reviewers` の実証研究と相補的な、概念整理側の研究。
- **差分・新規性（推定）**: AI レビューに特化したサーベイは初。Self-Correction セクションの `When AIs Judge AIs`(2508.02994)（LLM-as-a-Judge サーベイ）と並んで、**評価エージェントの体系化**の一部。

### 11.4 パーソナライズ研究エージェント

#### [May 2026] "NanoResearch: Co-Evolving Skills, Memory, and Policy for Personalized Research Automation" [[paper](https://arxiv.org/abs/2605.10813)]

- **概要（推定）**: 個別ユーザに特化した**小規模研究エージェント**。Skills, Memory, Policy を共進化させる。
- **差分・新規性（推定）**: 既存の研究エージェントは「**汎用的な科学者**」を目指していたが、本研究は **「特定研究者の研究を支援する小さなエージェント」** を提案。これは AI Scientist 懐疑論への現実的応答とも読める。`Towards Self-Evolving Agentic Literature Retrieval`([paper](https://arxiv.org/abs/2605.14306)) と組み合わせると、**個別研究者の長期パートナー**像が見える。

#### [May 2026] "Evaluating Memory Condensation Strategies for Coding Agents in Data-Driven Scientific Discovery"

- **概要（推定）**: データ駆動科学発見におけるコーディングエージェントの**メモリ圧縮戦略**を評価。長期研究タスクではコンテキストが爆発するため、メモリ圧縮が必須。
- **差分・新規性（推定）**: Research Agents と Memory 研究の交差点。Memory セクションで議論した「**メモリ腐敗**」とは別の、**スケーリング側の課題**を主題化。

### 11.5 横断的示唆

Research Agents の今期トレンドは **「汎用AI科学者の追求」から「個別研究者を支援する道具立て」** への重心移動。実装者向けTipsとして:

1. **完全自動化を目指さない**: `Agentic AI Scientists Are Not Built For Autonomous Scientific Discovery` の警告を真剣に受け止める。
2. **人間レビューを構造的に組み込む**: AI と人間の役割分担を明示。`On the limits and opportunities of AI reviewers` の知見を反映。
3. **パーソナライズを重視**: `NanoResearch` の発想で、特定ユーザ/分野に特化したエージェント。
4. **長期記憶の圧縮戦略**: 研究タスクは長期間にわたるため、`Evaluating Memory Condensation Strategies` の知見を活用。

## 12. Enterprise / Data / Finance: ガバナンスとスプレッドシート

### 12.1 このジャンルのトレンドと課題感

🔍 エンタープライズ採用フェーズでは、技術的能力よりも **(1) ガバナンス**、**(2) レガシー統合**、**(3) ドメイン固有の摩擦**（スプレッドシート、Excel ベースの業務等）が決定的な障壁となる。今期はこれらに正面から向き合う論文が増えている。残課題は、**ガバナンス・パフォーマンス・コストの三者最適化**。

### 12.2 設計時ガバナンス

#### [May 2026] "Governance by Construction for Generalist Agents" [[paper](https://arxiv.org/abs/2605.20874)]

- **概要（推定）**: 汎用エージェントに対する **「構築時点でのガバナンス（governance by construction）」** を提唱。後付けの監視ではなく、設計時点でガバナンス特性を組み込む。
- **差分・新規性（推定）**: 既存のガバナンス研究は**運用時の監視・監査**が中心だったが、本研究は**設計時の構造的組み込み**を提案。これは Safety セクションの `Position: Behavioural Assurance...`([paper](https://arxiv.org/abs/2605.15164)) と思想を共有する「**構造的安全**」潮流の Enterprise 版。

### 12.3 レガシーシステムの近代化

#### [May 2026] "Reversa: A Reverse Documentation Engineering Framework for Converting Legacy Software into Operational Specifications for AI Agents" [[paper](https://arxiv.org/abs/2605.18684)]

- **概要（推定）**: レガシーソフトウェアから**逆方向にドキュメント生成**し、AI エージェントが理解できる**運用仕様**に変換するフレームワーク。
- **差分・新規性（推定）**: 既存のレガシー近代化は**コード変換**が中心だったが、本研究は**仕様抽出**を主題化。これは AI エージェント時代における新しい近代化の意味で、**「エージェントが扱えるドキュメント形式」** という新しい工学要件を提示。

### 12.4 時系列・データ分析

#### [May 2026] "Detecting Time Series Anomalies Like an Expert: A Multi-Agent LLM Framework with Specialized Analyzers" [[paper](https://arxiv.org/abs/2605.05725)]

- **概要（推定）**: マルチエージェント LLM フレームワークで時系列異常を**専門家レベル**で検知。複数の特化アナライザがコラボレーションする設計。
- **差分・新規性（推定）**: 既存の時系列異常検知は単一モデルベースが多かったが、本研究は**専門家の分業構造**を模倣。`Agentic GraphRAG`(下記)・`Nexus`([paper](https://arxiv.org/abs/2605.14389)) と並んで、**金融・運用分析の Multi-Agent 化**潮流の一部。

#### [May 2026] "Nexus: An Agentic Framework for Time Series Forecasting" [[paper](https://arxiv.org/abs/2605.14389)] 🔥

- **概要**: Google/Penn State グループ（Das, Goyal, Parmar, Peng 等）による時系列予測のエージェントフレームワーク。
- **差分・新規性（推定）**: 既存の時系列予測モデル（Prophet, TimeGPT 等）が単一モデルアプローチだったのに対し、本研究は**エージェント的協調**を持ち込む。著者陣（Google Research の Tomas Pfister 等）から、商用化を視野に入れた重量級論文と推定される。

### 12.5 スプレッドシート操作の "再発見"

#### [May 2026] "WorkstreamBench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance" [[paper](https://arxiv.org/abs/2605.22664)] ⚖️

- **概要（推定）**: 金融分野での**end-to-end スプレッドシートタスク**を評価するベンチマーク。`SheetAgent`(2403.03636) や `SpreadsheetLLM` 系の流れを汲む。
- **差分・新規性（推定）**: 個別操作ではなく**ワークストリーム全体**（データ取得→分析→レポート生成）を評価。金融エージェントの**現実的なボトルネック**であるスプレッドシート操作に正面から向き合う。

#### [May 2026] "Spreadsheet-RL: Advancing Large Language Model Agents on Realistic Spreadsheet Tasks via Reinforcement Learning" [[paper](https://arxiv.org/abs/2605.22642)]

- **概要（推定）**: スプレッドシートタスクへの**強化学習**適用。`SheetMind`(2506.12339)・`SheetAgent`(2403.03636) の流れの先で、RL による性能向上を狙う。
- **差分・新規性（推定）**: スプレッドシート操作は**離散的・長期的・連鎖的**であり、RL の適用が難しかったが、本研究はその課題に取り組む。`MLE-STAR`(2506.15692) のような RL ベースエージェント研究の Excel 版。

### 12.6 ガバナンス付きエンタープライズ分析

#### [May 2026] "Beyond Text-to-SQL: An Agentic LLM System for Governed Enterprise Analytics APIs" [[paper](https://arxiv.org/abs/2605.21027)]

- **概要（推定）**: Text-to-SQL の単純な実装を超え、**ガバナンス付き分析 API**をエージェントが利用するシステム。アクセス制御・データガバナンス・部門間横断を考慮。
- **差分・新規性（推定）**: 既存の Text-to-SQL は**個別クエリ生成**が中心だったが、本研究は**ガバナンスが組み込まれた API 層**を介する。`AgenticRAG`([paper](https://arxiv.org/abs/2605.05538)) と並んで、エンタープライズ採用の**現実的要件**を主題化。

#### [May 2026] "Building AI Companions that Prioritise Learning over Performance" [[paper](https://arxiv.org/abs/2605.04816)]

- **概要（推定）**: AIコンパニオン設計において、**パフォーマンス（タスク達成）より学習（ユーザの成長）** を優先する。教育・コーチング系のエージェント設計に関する規範論文と推定。
- **差分・新規性（推定）**: 既存のエージェント研究は性能向上が主目的だったが、本研究は **「ユーザ学習を阻害しないエージェント」** という新しい設計目標を提示する。スキルアップを支援する企業向けエージェントの設計に影響しうる。

### 12.7 NOT_FOUND論文

- **"Agentic GraphRAG: Navigating Unstructured Financial Data with Collaborative AI"**: 非構造化金融データへの GraphRAG。`Agentic Information Retrieval`(2410.09713) の金融特化版と推定。

### 12.8 横断的示唆

Enterprise / Data / Finance の今期トレンドは **「ガバナンス・レガシー・スプレッドシート」** という地味だが現実的な3課題への正面突破。実装者向けTipsとして:

1. **ガバナンスを設計時に組み込む**: `Governance by Construction` の発想。後付けは破綻する。
2. **レガシーシステムからの仕様抽出**を AI ワークフローの最初のステップに（`Reversa` の発想）。
3. **時系列・データ分析はマルチエージェント設計を検討**: `Nexus` や `Detecting Time Series Anomalies Like an Expert` の発想。
4. **スプレッドシート操作の能力を独立評価**: `WorkstreamBench` で自社モデルを測る。
5. **Text-to-SQL は出発点であって到達点ではない**: `Beyond Text-to-SQL` の発想で、API 層・ガバナンス層を分離設計。

## 13. Digital Agents: GUI/Computer-Use 評価の現実化

### 13.1 このジャンルのトレンドと課題感

🔍 GUI/Computer-Use Agents は2024〜2025年に `OSWorld`(2404.07972)、`UI-TARS`(2501.12326) など基盤が整い、Apr 2026 の `On the Reliability of Computer Use Agents`(2604.17849) で実用化フェーズに入った。今期は**メモリ統合**と**SaaS統合**という具体的な実用課題が論点に。

### 13.2 GUI エージェントへのメモリ統合

#### [May 2026] "Executable Agentic Memory for GUI Agent"

- **概要（推定）**: GUI エージェントに**実行可能なメモリ（executable memory）** を導入。過去の操作シーケンスを再利用可能な形で保存。
- **差分・新規性（推定）**: 既存の GUI エージェントは**観測ベース**のメモリが中心だったが、本研究は **操作シーケンス自体をメモリとして実行可能** にする。`MGA: Memory-Driven GUI Agent`(2510.24168) の発展形と見ることができる。

#### [May 2026] "SaaS-Bench: Can Computer-Use Agents Leverage Real-World SaaS to Solve Professional Workflows?"

- **概要（推定）**: 実世界の SaaS（Salesforce, Slack, Notion 等）を使ったプロフェッショナルワークフローを評価するベンチマーク。
- **差分・新規性（推定）**: `SCUBA: Salesforce Computer Use Benchmark`(2509.26506) の汎化版。複数 SaaS にまたがる**実務的なワークフロー**を評価。`WildClawBench`([paper](https://arxiv.org/abs/2605.10912)) と思想を共有する「**Wild benchmark**」潮流の一部。

## 14. Capability Papers (横断的): Knowledge, Learning, Reasoning

### 14.1 Knowledge

#### [May 2026] "PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents" [[paper](https://arxiv.org/abs/2605.19932)]

- **概要（推定）**: 長コンテキスト LLM エージェント向けの**コンテキストマップ**を「方向性キャッシュ（orientation cache）」として提供。コンテキスト内の重要箇所への素早いアクセスを可能にする。
- **差分・新規性（推定）**: 長コンテキスト研究は**注意機構の改善**が中心だったが、本研究は**コンテキスト構造の補助インデックス**という新しい層を提示。

#### [May 2026] "From Chat to Interview: Agentic Requirements Elicitation with an Experience Ontology"

- **概要（推定）**: 要件抽出（requirements elicitation）を**チャットからインタビュー形式へ**進化させるエージェント。経験オントロジー（experience ontology）を活用。
- **差分・新規性（推定）**: ソフトウェア工学の要件抽出を AI エージェント化する珍しい論文。Software Agents との接続を狙う。

### 14.2 Learning

#### [May 2026] "Generate, Filter, Control, Replay: A Comprehensive Survey of Rollout Strategies for LLM Reinforcement Learning" [[paper](https://arxiv.org/abs/2605.02913)] 📖

- **概要（推定）**: LLM RL における**ロールアウト戦略**を体系的にサーベイ。生成・フィルタ・制御・リプレイの4軸で整理。
- **差分・新規性（推定）**: LLM RL の急速な発展（Agent-RLVR(2506.11425)、PivotRL(2603.21383) 等）の中で、ロールアウト戦略に特化したサーベイは初。実装者にとって**設計選択のガイドライン**として価値が高い。

#### [May 2026] "On Training Large Language Models for Long-Horizon Tasks: An Empirical Study of Horizon Length" [[paper](https://arxiv.org/abs/2605.02572)]

- **概要（推定）**: 長期タスクの訓練における**ホライズン長（horizon length）の影響**を実証研究。
- **差分・新規性（推定）**: 長期タスク訓練は重要だが、ホライズン長を独立変数として系統的に研究した論文は少ない。`DEEPPLANNER`(2510.12979) や `Demystifying Reinforcement Learning for Long-Horizon Tool-Using Agents`(2603.21972) の流れを補完する empirical study。

#### [May 2026] "Learning Agentic Policy from Action Guidance" [[paper](https://arxiv.org/abs/2605.12004)]

- **概要（推定）**: エージェントポリシーを**アクションガイダンス**（行動指示）から学習する。模倣学習と RL の中間的なアプローチ。
- **差分・新規性（推定）**: 既存のエージェント学習は報酬ベースか模倣ベースが中心だったが、本研究は**ガイダンス**という中間表現を活用。SFT (Supervised Fine-Tuning) と RLHF の中間的な設定。

#### [May 2026] "Compiling Agentic Workflows into LLM Weights: Near-Frontier Quality at Two Orders of Magnitude Less Cost"

- **概要（推定）**: エージェント的ワークフロー（複数ステップの推論・ツール呼び出し）を **LLM の重みにコンパイル**することで、推論コストを大幅削減（2桁減）しながら近似的なフロンティア品質を保つ。
- **差分・新規性（推定）**: エージェント実行時のオーケストレーションコストが課題化する中、**ワークフローを蒸留してモデル内部化**するアプローチ。実用化フェーズの重要なコスト削減技術。

### 14.3 Reasoning

#### [May 2026] "Tools as Continuous Flow for Evolving Agentic Reasoning" [[paper](https://arxiv.org/abs/2605.07339)]

- **概要（推定）**: ツールを**離散呼び出しではなく連続フロー**として扱い、エージェント推論を進化させる。
- **差分・新規性（推定）**: 既存のツール呼び出しは離散的・同期的だったが、本研究は**ストリーミング・非同期**な連続フローを提案。`HEAVYSKILL`([paper](https://arxiv.org/abs/2605.02396)) と思想を共有する「**推論プロセス自体の再設計**」潮流の一部。

#### [May 2026] "INFERENCEBENCH: A Benchmark for Open-Ended LLM Inference Optimization by AI Agents"

- **概要（推定）**: LLM 推論の最適化（推論コスト、レイテンシ等）を **AI エージェント自身が行う**ベンチマーク。
- **差分・新規性（推定）**: メタレベルの研究で、**AI が AI を最適化する**という MLOps エージェント化の流れ。Self-Evolution セクションの再帰的最適化と通底する。

### 14.4 Planning

#### [May 2026] "Planning in the LLM Era: Building for Reliability and Efficiency" [[paper](https://arxiv.org/abs/2605.21902)] 📖

- **概要（推定）**: LLM 時代の計画立案を**信頼性と効率性**の観点から整理するサーベイ。`Understanding the planning of LLM agents: A survey`(2402.02716) 以来の包括的サーベイと推定される。
- **差分・新規性（推定）**: `PlanGenLLMs`(2502.11221)、`Large Language Models for Planning: A Comprehensive and Systematic Survey`(2505.19683) の流れを汲み、**信頼性と効率性**という運用視点を主軸に置く。`From Plan to Action: How Well Do Agents Follow the Plan?`(2604.12147) の実証研究と相補的。

## 15. 横断テーマ: 全エージェント研究を貫く共通課題

### 15.1 課題1: 長期運用での「腐敗」問題

- **メモリ腐敗**: `Useful Memories Become Faulty`([paper](https://arxiv.org/abs/2605.12978))、`STALE`([paper](https://arxiv.org/abs/2605.06527))
- **検索品質の劣化**: `LongSeeker`([paper](https://arxiv.org/abs/2605.05191))
- **スキルの陳腐化**: `SkillsVote`([paper](https://arxiv.org/abs/2605.18401))
- **ワークフロー劣化**: `GraphMind`

**横断的解法**: **TTL / Validity Window / Supersedes リレーション** を一級市民として扱う。

### 15.2 課題2: 評価の現実性ギャップ

- **静的ベンチでの成功 ≠ 実世界での成功**: `WildClawBench`([paper](https://arxiv.org/abs/2605.10912))、`From Controlled to the Wild`([paper](https://arxiv.org/abs/2605.10834))
- **ベンチ汚染**: `FrontierSmith`([paper](https://arxiv.org/abs/2605.14445)) の合成データが汚染源にもなる

**横断的解法**: **Live Benchmark / 環境rollout / 連続評価** をデフォルトに。

### 15.3 課題3: 失敗帰属

- **マルチエージェント系で誰の失敗か特定できない**: `Beyond Individual Intelligence`([paper](https://arxiv.org/abs/2605.14892)) サーベイ
- **スキルが原因かハーネスが原因か区別できない**: `Counterfactual Trace Auditing`([paper](https://arxiv.org/abs/2605.11946))

**横断的解法**: **因果的トレース監査**、構造化ログ、トレースID 伝播。

### 15.4 課題4: 安全と性能のトレードオフ

- **スキルが攻撃ベクタにもなる**: `Proteus`、`SkillScope`([paper](https://arxiv.org/abs/2605.05868))
- **ツール出力が信頼できない**: `Trust No Tool`([paper](https://arxiv.org/abs/2605.17453))
- **行動評価では捉えられない**: `Position: Behavioural Assurance...`([paper](https://arxiv.org/abs/2605.15164))

**横断的解法**: **最小権限原則のスキル単位適用**、**ツール出力の検証ラッパー**、**形式的安全保証への接続**。

### 15.5 課題5: コスト・効率

- **エージェントは推論コストが高い**: `Compiling Agentic Workflows into LLM Weights`
- **並列スケーリングの困難さ**: `Scaling Retrieval-Augmented Reasoning with Parallel Search`

**横断的解法**: **ワークフローの重みへのコンパイル**、**明示的な parallel-merge**、**context 圧縮**。

### 15.6 課題6: ユーザ理解可能性

- **スキル仕様がエンドユーザに理解できない**: `Toward User Comprehension Supports`
- **失敗の説明可能性**: `Counterfactual Trace Auditing`([paper](https://arxiv.org/abs/2605.11946))

**横断的解法**: **仕様の自然言語化**、**UX研究との接続**。

### 15.7 課題7: ガバナンスと規制

- **行動評価では不十分**: `Position: Behavioural Assurance...`
- **エンタープライズコンテキスト要件**: `Governance by Construction`([paper](https://arxiv.org/abs/2605.20874))

**横断的解法**: **設計時ガバナンス**（Governance-by-Design）、**ホワイトボックス監査**。

## 16. 共通の解法パターン7選

### パターン A: Hygiene Layer（衛生層）

進化・更新・統合の前後に**整合性チェック・冪等性・ロールバック**を強制する層を入れる。

- メモリ更新の整合性検証 (`Ratchet`([paper](https://arxiv.org/abs/2605.22148))、`STALE`([paper](https://arxiv.org/abs/2605.06527)))
- スキル更新のレビュー (`SkillsVote`([paper](https://arxiv.org/abs/2605.18401)))
- ワークフロー更新の影響範囲分析 (`GraphMind`)

### パターン B: Adaptive Interface（適応的インターフェース）

モデルではなくインターフェース側を環境/タスクに適応させる。

- `Adapting the Interface, Not the Model`([paper](https://arxiv.org/abs/2605.22166))
- `Code as Agent Harness`([paper](https://arxiv.org/abs/2605.18747))
- `Is Grep All You Need?`([paper](https://arxiv.org/abs/2605.15184))

### パターン C: Causal Trace（因果トレース）

実行トレースから因果関係を抽出し、失敗帰属・進化判断・監査に使う。

- `Counterfactual Trace Auditing of LLM Agent Skills`([paper](https://arxiv.org/abs/2605.11946))
- `GraphMind: From Operational Traces to Self-Evolving Workflow Automation`
- `EXG: Self-Evolving Agents with Experience Graphs`

### パターン D: Lifecycle Governance（ライフサイクル統治）

生成・利用・廃棄を一貫して管理する。

- `SkillsVote: Lifecycle Governance of Agent Skills`([paper](https://arxiv.org/abs/2605.18401))
- `Governance by Construction for Generalist Agents`([paper](https://arxiv.org/abs/2605.20874))
- `SafeHarbor: Defining Precise Decision Boundaries`([paper](https://arxiv.org/abs/2605.05704))

### パターン E: Capability Ladder（能力ラダー）

「できる/できない」を段階的に測る代わりに、難易度の階段で評価する。

- ⚖️ `ExploitBench: A Capability Ladder Benchmark`([paper](https://arxiv.org/abs/2605.14153))
- `WildClawBench`([paper](https://arxiv.org/abs/2605.10912))、`MEMGYM`([paper](https://arxiv.org/abs/2605.20833))、`EvoMemBench`([paper](https://arxiv.org/abs/2605.18421))

### パターン F: Validity-aware Memory（有効性意識型メモリ）

記憶に妥当性ウィンドウ・条件付き有効性を埋め込む。

- `STALE`([paper](https://arxiv.org/abs/2605.06527))
- `Rethinking How to Remember`([paper](https://arxiv.org/abs/2605.19952))
- `Useful Memories Become Faulty...`([paper](https://arxiv.org/abs/2605.12978)) の警告への応答

### パターン G: Parallel-Explicit-Merge（並列・明示的マージ）

並列探索 + マージ過程の明示化で透明性・スケーラビリティを両立。

- `Scaling Retrieval-Augmented Reasoning with Parallel Search and Explicit Merging`
- `Recursive Agent Optimization`([paper](https://arxiv.org/abs/2605.06639))（再帰的並列化）

## 17. 実装者向けTips集（保存版）

### 17.1 メモリシステムを設計するとき

1. **書き込み時にメタデータを必ず付ける**
   `{content, written_at, valid_until?, source_trace_id, supersedes?: [...]}`
   特に `valid_until` と `supersedes` は後で**腐敗対策**に効く。
2. **取り出し時に必ず "stale check"** を挟む（`STALE`([paper](https://arxiv.org/abs/2605.06527)) の示唆）
3. **更新ではなく append-only**: 上書きは原則禁止、新しいレコードで「supersedes 旧レコード」と記述
4. **`Useful Memories Become Faulty`([paper](https://arxiv.org/abs/2605.12978)) の知見**: LLMによるメモリ自動更新パイプラインには、**改竄検出器**を必ず外側に置く
5. **オフライン consolidation pass** (`Auto-Dreamer`([paper](https://arxiv.org/abs/2605.20616))): 定期的にメモリを整理・統合する batch job

### 17.2 Skillを設計・運用するとき

1. **トリガー（when）と権限（permission）を必ず明示** （`SkillScope`([paper](https://arxiv.org/abs/2605.05868))）
2. **トレースで使用状況を全記録** （`Counterfactual Trace Auditing`([paper](https://arxiv.org/abs/2605.11946))）
3. **生成パイプラインを持つなら、評価ハーネスもセットで** （`SkillGenBench`([paper](https://arxiv.org/abs/2605.18693))）
4. **赤チーム化を運用に組み込む** （`Proteus` の発想）
5. **ライフサイクルイベント**（誕生・進化・廃棄）を明示的にログ
6. **多数決ガバナンス** （`SkillsVote`([paper](https://arxiv.org/abs/2605.18401))）でスキル採用を判断

### 17.3 マルチエージェント系を組むとき

1. **状態管理を明示的に**（`Multi-agent Collaboration with State Management`([paper](https://arxiv.org/abs/2605.20563))）
2. **失敗帰属用のトレースID**を全メッセージに伝播（`Beyond Individual Intelligence`([paper](https://arxiv.org/abs/2605.14892)) サーベイの推奨）
3. **ベイズ整合性チェック**: 異なるエージェント間で確率推論が矛盾しないか確認（`Bayes-consistent orchestration`([paper](https://arxiv.org/abs/2605.00742))）
4. **再帰的最適化**: 最適化ループ自体をエージェント化する設計を検討（`Recursive Agent Optimization`([paper](https://arxiv.org/abs/2605.06639))）

### 17.4 安全性を担保するとき

1. **行動評価だけに依存しない**（`Position: Behavioural Assurance...`([paper](https://arxiv.org/abs/2605.15164))）
2. **ハーネスレベルの監査**を併用（`Auditing Agent Harness Safety`([paper](https://arxiv.org/abs/2605.14271))）
3. **ツール出力を信頼しない設計**（`Trust No Tool`([paper](https://arxiv.org/abs/2605.17453))）
4. **設計時ガバナンス**: 後付けは破綻する（`Governance by Construction`([paper](https://arxiv.org/abs/2605.20874))）
5. **可観測性をシステム設計の第一級要件**（`Visibility into AI Agents`([paper](https://arxiv.org/abs/2401.13138))）

### 17.5 コーディングエージェントを運用するとき

1. **生成より保守を評価**（`To What Extent Does Agent-generated Code Require Maintenance?`([paper](https://arxiv.org/abs/2605.06464))）
2. **修復は根本原因にこだわる**（`Root-Cause-Driven Automated Vulnerability Repair`([paper](https://arxiv.org/abs/2605.04251))）
3. **リポジトリ階層メモリ**（`MemRepair`([paper](https://arxiv.org/abs/2605.17444))）
4. **コードレビュー側もエージェント化**（`Rethinking Code Review in the Age of AI`）

### 17.6 検索/Retrievalを設計するとき

1. **長期検索ではコンテキストを弾性的に**（`LongSeeker`([paper](https://arxiv.org/abs/2605.05191))）
2. **並列探索の結果は明示的にマージ**（説明可能性のため）
3. **エンタープライズコンテキストではGovernance層を分離**（`Beyond Text-to-SQL`([paper](https://arxiv.org/abs/2605.21027))）
4. **検索戦略自体を経験から学ぶ**（`Towards Self-Evolving Agentic Literature Retrieval`([paper](https://arxiv.org/abs/2605.14306))）

### 17.7 Harness/環境を設計するとき

1. **インターフェースの適応で多くの問題が解ける**（`Adapting the Interface, Not the Model`([paper](https://arxiv.org/abs/2605.22166))）
2. **ハーネスをコードとして扱う**（`Code as Agent Harness`([paper](https://arxiv.org/abs/2605.18747))） → バージョン管理・テスト可能に
3. **既存ツール（grep等）でも強力**（`Is Grep All You Need?`([paper](https://arxiv.org/abs/2605.15184))）── 過剰な抽象化を避ける
4. **ハーネス安全性も監査対象**（`Auditing Agent Harness Safety`([paper](https://arxiv.org/abs/2605.14271))）

## 19. まとめ：今期のメッセージ

> **「賢いモデル」から「賢く運用可能なシステム」へ。**

今期のエージェント研究は、明らかに次のフェーズに入った。論文タイトルが示すように、コミュニティの関心は次のように移っている:

- **モデルの能力スコア** → **運用可能性・監査性・寿命**
- **新しい技法の提案** → **失敗パターンの体系化・批判的サーベイ**
- **個別タスクのSOTA** → **ライフサイクル全体の設計**

これは、エージェント研究が **「論文を書く研究」から「製品を作るための研究」** へ成熟しつつある証拠とも言える。

特に次の3本は、今期のフラッグシップ論文として記憶すべき:

1. **`Position: Behavioural Assurance Cannot Verify the Safety Claims Governance Now Demands`** ([paper](https://arxiv.org/abs/2605.15164))
   ── **評価**の根幹への根源的疑義。

2. **`Useful Memories Become Faulty When Continuously Updated by LLMs`** ([paper](https://arxiv.org/abs/2605.12978))
   ── **メモリ**の根幹への根源的疑義。

3. **`Agentic AI Scientists Are Not Built For Autonomous Scientific Discovery`** ([paper](https://arxiv.org/abs/2605.08956))
   ── **自律性**の幻想への根源的疑義。

これらの「**根源的疑義の3部作**」は、今後数ヶ月の研究議論を牽引する可能性が高い。

同時に、`A Comprehensive Survey on Agent Skills`([paper](https://arxiv.org/abs/2605.07358))・`Beyond Individual Intelligence`([paper](https://arxiv.org/abs/2605.14892))・`Generate, Filter, Control, Replay`([paper](https://arxiv.org/abs/2605.02913))・`Planning in the LLM Era`([paper](https://arxiv.org/abs/2605.21902)) という4本のサーベイが同時期に出たことは、**各サブ分野が「整理を要する成熟段階」に達した**ことを示している。
