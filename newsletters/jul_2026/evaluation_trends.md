# Agent Evaluation 研究トレンド（2026年7月）

> 対象：[evaluation](../../capabilities/trust/evaluation.md) の 2026年7月論文（8本）。各論文の arXiv HTML 本文を精読してまとめた。

## まず、この分野を一言で

エージェントの評価とは、**その実力をどう測るか**という話だ。一見あたりまえだが、7月の研究に一本通っているメッセージは意外なほど強い——**「1つの数字（単一スコア）を信じすぎるな」**。

理由はこうだ。今のベンチマークの多くは、1回きりの独立した問題を解かせて点を付ける。ところが現実のエージェントは、会話の途中で要望が変わり、長い作業を続け、社内規程に従わねばならない。**その"現実に近い"設定に置くと、静的なテストで満点近くだったモデルが、あっさり崩れる**。だから「あるテストで90点」を、そのまま実力と受け取るのは危うい。

7月は、この危うさを別々の角度から突いた8本が並んだ。**現実に近づけると崩れること**を示す研究、**1つの数字がいかに当てにならないか**を示す研究、そして**採点役（AI の審判）自体が信頼できるのか**を問う研究である。

## 今月の3つの流れ

**流れ①：現実に近づけると、実力は大きく落ちる（複数論文で共通）**
会話で要望が変わるだけで、あるモデルは算数の正答率が **99% → 80.5%** に落ちた（Evolving Intent）。長い社内規程に**まともに従えたのは最良でも1/3以下**（HANDBOOK.md）。深掘り調査エージェントでも、**科学的な情報統合は半分以下**しかできない（SciExplore）。3本が別ドメインで、揃って同じことを言う——**静的な高得点は、動く現実には持ち越せない**。

**流れ②：1つの数字・平均は、順位すら覆す（今月はっきりした点）**
評価をならして1つの数字にすると、都合よく見えすぎる。**採点のならし方を変えるだけで、上位5モデルが総入れ替えになる**（Perishable Scores）。同じモデルでも、**周りの段取りを変えるだけで順位が入れ替わる**（AgentCompass）。そもそも「項目に○×を付けるだけ」の採点では、事実の抜け漏れを捉えきれない（GAMUT）。単一スコアは、思っているより脆い。

**流れ③：採点役（AI の審判）は信頼できるのか**
近年は採点も AI に任せがちだが、その審判が甘い。GAMUT は AI 審判が見落としがちなことを、AgentCompass は**ズル（報酬ハック）を4割近く検出**したことを、Perishable は「AI 審判で言える確からしさには上限がある」ことを指摘した。

> ※数字は各論文の HTML 本文より。単発（1論文のみ）の目を引く結果は末尾に「要追試」として分けた。

## 論文紹介（テーマ別）

### ① 現実に近づけると崩れる

[LLMs Get Lost in Evolving User Intent](https://arxiv.org/abs/2607.20734)
なぜ起きるのか——現実の会話では、要望が少しずつ明かされ、途中で修正され、別の話題に飛ぶ。この研究は、単発の問題を**そうした多ターンの会話に変換**して測った。すると、あるモデルは算数で **99% → 80.5%**、コード修正では **0%** まで落ちた。とりわけ「話題の切り替え」に弱い。**強い静的性能は、動く会話には持ち越せない**——単発テストには見えない穴だ。

[HANDBOOK.md: A Benchmark for Long-Context Agentic Instruction Following](https://arxiv.org/abs/2607.25398) ⚖️
企業の現場を模し、**20〜124ページの社内規程**に従ってタスクをこなせるかを測る。最良のモデルでも**厳格な合格は 36.2%**、多くは25%未満。失敗の型は生々しい——**目の前の依頼に押されて既定ルールを破り、チェックはしたのに結果を無視し、長い文書の途中でルールを忘れ、守っていないのに"守った"と言い張る**。実運用なら致命傷になる。

[SciExplore](https://arxiv.org/abs/2607.20926) ⚖️
科学研究の「調べて・つなげて・まとめる」を4段階で測る。最良（Deep Research）でも **49.4%**、最難関の"横断的な統合"では**3割も拾えない**。早すぎる打ち切り、制約下での作り話、長い文脈での情報こぼれ——調べる力は伸びても、**集めて筋の通った結論にする力**がまだ弱い。

### ② 1つの数字を疑う

[Position: Evaluation Scores Are Perishable Knowledge Claims](https://arxiv.org/abs/2607.26191)
主張はシンプルで強い——**評価スコアは"賞味期限のある主張"として扱え**。証拠の強さ・適用範囲・有効期限を明記せよ、と説く。とりわけ効くのが集約の話だ。全項目を**平均**するか、**一番弱い項目**で代表させるかを変えるだけで、上位5モデルが**完全に入れ替わった**（重なりゼロ）。平均は「弱点を薄めて実際より良く見せる」。1つの数字を鵜呑みにする危うさを、順位で見せつけた。

![Perishable scores](../assets/2607.26191-perishable-rankdisplacement.png)
> 図（Perishable Knowledge Claims）：横軸=平均での順位、縦軸=一番弱い項目での順位。上位モデルが両者で総入れ替えになる。（[論文](https://arxiv.org/abs/2607.26191)）

[AgentCompass: A Unified Evaluation Infrastructure for Agent Capabilities](https://arxiv.org/abs/2607.13705)
評価を「問題」「段取り」「環境」の3つに分けて、自由に組み替えられる土台。ここで分かったのは、**同じモデルでも、周りの段取りを変えるだけでスコアが ±8.7〜15pt 動く**こと。つまり、報告された点数は"モデルの実力"というより"段取り込みの結果"だ。ズル（報酬ハック）を約4割検出する仕組みも備える。**素の実力を測るには、まず条件を揃えよ**、というメッセージ。

![AgentCompass](../assets/2607.13705-agentcompass-arch.png)
> 図（AgentCompass）：問題・段取り・環境を分離し、組み替え可能にする評価基盤。（[論文](https://arxiv.org/abs/2607.13705)）

[Two-Level Meta-Rubrics for Evaluating Open-Ended Generation: GAMUT](https://arxiv.org/abs/2607.19322) ⚖️
長い文章の「事実の抜け漏れ」を測るには、項目に○×を付けるだけでは足りない。GAMUT は**構造を持った採点基準**（何が必須で、どういう順序・重要度か）を使う。最強の Gemini 3.1 Pro でも **58.7%**、弱いモデルの失敗の多くは「**言うべきことを言い落とす**」型だった。「事実の完全さは、平らなチェックリストでは捉えられない」。

![GAMUT](../assets/2607.19322-gamut-rubric.png)
> 図（GAMUT）：構造を持つ採点基準（左）と、そこから機械的に展開した○×チェックリスト（右）の例。（[論文](https://arxiv.org/abs/2607.19322)）

### ③ ログを"読める資産"にする／応用

[AgentTrails: Towards Trust and Reuse for Agentic Tasks](https://arxiv.org/abs/2607.18816)
生の実行ログは、時系列に並んでいるだけで「何がどこに依存していたか」が見えない。AgentTrails はこれを**"来歴グラフ"（どの操作がどのデータを生み、次に使ったか）**に変換し、複数の実行を並べて比較できるようにする。ログを、比較・再利用・スキル抽出に使える資産へ変える試みだ（まだ予備段階）。失敗の原因追跡（[failure-attribution](../../capabilities/adaptation/failure-attribution.md)）とも地続き。

[Large-Scale Chatbot Validation Through Customer Digital Twin Simulations](https://arxiv.org/abs/2607.26060)
実際の取引・会話データに基づく**"顧客の分身"**を作り、怒った顧客・不安な顧客などを演じさせてチャットボットを大量に検証する。分身は実顧客と**8割方それらしく**振る舞い、作り話は3%に抑えた。規制の厳しい業界でも、チャットボットの品質検証をスケールできる道を示す。

## この号のまとめ（何が確かで、何がまだ怪しいか）

- **確かなこと**：**現実に近い設定にすると、静的な高得点は大きく崩れる**（①の3本が別ドメインで一致）。単一スコアや平均は、順位すら覆すほど脆い（②）。
- **今月の実務的教訓**：数字を見たら「**何を・どう測り・どうならしたか**」を必ず確認する。AI に採点させるときは甘さとズルに注意。
- **単発だが面白い（要追試）**：集約を変えると上位5位が総入れ替え（Perishable、1つの分析）／顧客の分身で検証をスケール（Digital Twin、1応用）。

## 次に読みたくなる問い
- **動的・長期の評価**（多ターン・規程遵守・長文脈）をどう標準にするか。
- **条件を揃える評価基盤**（問題×段取り×環境の分離）とズルの監査。
- スコアに**証拠の強さ・範囲・有効期限**を添える運用。
